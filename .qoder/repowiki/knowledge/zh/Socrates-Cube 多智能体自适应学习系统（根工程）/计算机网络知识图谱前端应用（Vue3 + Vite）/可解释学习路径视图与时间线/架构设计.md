模块按 Vue3 + Pinia 的单向数据流组织：
- `views/PathView.vue` 作为页面入口，在 `onMounted` 中同时拉取用户画像与学习路径，并挂载 `PathReasonModal` 弹窗。
- `stores/pathStore.ts` 通过 `defineStore('path')` 维护 `LearningPath | null`、`selectedNode`、`loading/error` 等响应式状态，并提供 `fetchPath`（调用 `api/path.ts`）、`updateFromSSE`（接收 SSE path_update 事件直接替换路径）、`markNodeCompleted`（乐观更新当前节点为 completed，并递归将满足 prerequisites 的 locked 后继节点提升为 pending）以及 `selectNode` 等动作；`completedCount / totalCount / progressPercent` 以 computed 派生。
- `api/path.ts` 暴露 `pathApi` 对象，封装 GET `/api/v1/path/:userId`、POST `/api/v1/path/plan`、POST `/api/v1/path/:userId/progress` 三个 REST 端点，统一经 `api/client` 发起请求并解包 `.data`。
- `types/path.ts` 定义前后端契约：`PathNodeStatus` 联合类型、`PathNode`（后端返回字段 snake_case）、`LearningPath`、`PathReasonSources`（graph_dependency/diagnosis_result/cognitive_style 三源），并导出 `hasPathReasonSources` 类型守卫。
- `components/PathTimeline.vue` 是纯展示组件，内部用本地 `ref<LearningPathNode[]>` 模拟数据渲染时间线、进度条与统计面板，并通过 `el-dialog` 弹出三维理由详情；该组件目前尚未接入 store，属于独立演示实现。
依赖方向：view → store → api → types，组件不直接访问 API。
