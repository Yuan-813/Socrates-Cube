## 项目结构
前端位于 frontend 子目录，采用按“能力域”划分的目录组织方式：
- src/api：HTTP 客户端与各业务接口定义
- src/composables：组合式函数（API 调用、SSE 等）
- src/stores：Pinia 状态模块
- src/components：可复用 UI 组件
- src/views：页面级视图
- src/types：全局类型定义
- 根配置：vite.config.ts、tailwind.config.js、postcss.config.js、package.json

### 状态管理模式（Pinia）
- 设计原则：
  - 以领域为中心拆分 store（认证、聊天、路径、资源、模拟器、用户）
  - 将副作用（网络请求、事件监听）集中在组合式函数或 store actions 中
  - 保持 state 最小化，派生状态通过 getters 计算
- 典型流程：
  - 组件触发 action -> 调用 useApi -> 更新 store -> 视图响应式更新

```mermaid

participant Client as "client.ts"
participant Mock as "mockInterceptor.ts"
View->>Store : "发送消息动作"
Store->>Compose : "调用 API 组合式"
Compose->>Client : "发起 HTTP 请求"
Client->>Mock : "命中 Mock 时拦截"
Mock-->>Client : "返回模拟数据"
Client-->>Compose : "返回响应"
Compose-->>Store : "解析并落库"
Store-->>View : "state 变更驱动渲染"
```

### API 客户端与 Mock 拦截
- 统一客户端：
  - 封装基础 URL、超时、重试、错误码处理、鉴权头注入
  - 提供类型安全的请求方法
- Mock 策略：
  - 通过拦截器在开发环境或特定条件下返回模拟数据
  - 便于联调与离线演示

```mermaid
flowchart TD
Start(["发起请求"]) --> CheckEnv{"是否启用 Mock?"}
CheckEnv --> |是| Intercept["mockInterceptor 拦截"]
CheckEnv --> |否| Real["client 真实请求"]
Intercept --> ReturnMock["返回模拟数据"]
Real --> Response{"响应成功?"}
Response --> |是| Parse["解析并返回"]
Response --> |否| HandleErr["统一错误处理"]
Parse --> End(["完成"])
ReturnMock --> End
HandleErr --> End
```

### 实时通信（SSE）
- 使用组合式函数封装 SSE 连接生命周期：建立、心跳、重连、断线提示、消息分发
- 与 store 联动：收到服务端推送后更新对应状态
- 注意事项：
  - 组件销毁时主动关闭连接，避免内存泄漏
  - 对重复订阅进行去抖/节流控制
