2. **能力递进原则**：对标网络工程师认证路径(CCNA→CCNP→CCIE)的知识递进逻辑

## 规划原则

### 1. 协议栈依赖链（硬约束，不可违反）
以下依赖关系反映协议栈层次结构，上层知识点必须在下层掌握后学习：
```
物理层概念(kp_004) → 数据链路层(kp_005) → 局域网技术(kp_006)
                                            ↓
网络层概念(kp_007) → IP地址/子网(kp_008) → ARP(kp_009) → 路由选择(kp_010)
                                            ↓
运输层概念(kp_011) → UDP(kp_012) → TCP基础(kp_013) → TCP握手(kp_014) → TCP流控/拥塞(kp_015)
                                                                         ↓
应用层概念(kp_016) → DNS(kp_017) → HTTP/HTTPS(kp_018) → 网络安全(kp_019)
                                                                         ↓
                                                        综合故障排查(kp_020)
```

### 2. 关键前置知识映射（常见依赖遗漏）
| 目标知识点 | 必要前置知识 | 原因 |
|-----------|------------|------|
| TCP拥塞控制(kp_015) | 滑动窗口(kp_013) + IP分片(kp_007) | cwnd调节需理解窗口机制；拥塞发生在IP层路径上 |
| HTTPS(kp_018) | TCP(kp_013) + 网络安全基础(kp_019) | TLS建立在TCP之上；需理解加密/认证基本概念 |
| DNS(kp_017) | UDP(kp_012) + IP路由(kp_010) | DNS查询走UDP 53端口；递归查询需理解路由可达性 |
| BGP路由(kp_010) | 子网划分(kp_008) + OSPF基础 | BGP路由策略基于CIDR前缀；需先理解IGP |
| 故障排查(kp_020) | 全部前置层次知识 | 端到端分析需要每一层的诊断能力 |

### 3. 优先级排序策略
按以下优先级降序排列：
1. **薄弱前置知识补救**：诊断发现的薄弱节点中，作为其他节点前置依赖的优先修补
2. **知识断链修复**：当前学习节点的直接前置知识存在缺口时，优先补齐
3. **最近发展区(ZPD)**：选择略高于当前水平但通过指导可达的知识点
4. **学习效率最大化**：一个知识点能同时修复多个误解时优先安排

### 4. 实验环节嵌入
每个路径节点应建议配套的实践活动：
- 协议理解类 → Wireshark抓包观察（过滤器表达式建议）
- 地址计算类 → 子网划分计算练习（VLSM场景）
- 编程实践类 → Socket编程实验（Python标准库）
- 故障排查类 → 模拟故障诊断（分层排查方法论）
- 安全分析类 → 攻防场景模拟（TLS证书验证、ARP欺骗原理）

### 5. 认证路径对标
- **CCNA级**（入门）：协议基本概念、地址配置、简单路由
- **CCNP级**（进阶）：协议交互分析、拥塞控制算法、路由策略
- **CCIE级**（专家）：协议设计权衡、性能优化、复杂故障定位
