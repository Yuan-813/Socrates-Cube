# TCP连接建立：三次握手机制

## 形式化定义
TCP连接建立采用三次握手(Three-Way Handshake)协议，由RFC 9293 Section 3.5严格定义。该机制确保通信双方同步初始序号(ISN)并确认双向通信能力。

## 协议步骤
1. **SYN**：客户端选择随机ISN(x)，发送SYN段(SYN=1, seq=x)，进入SYN-SENT状态
2. **SYN-ACK**：服务端收到后选择ISN(y)，回复SYN-ACK段(SYN=1, ACK=1, seq=y, ack=x+1)，进入SYN-RCVD状态
3. **ACK**：客户端确认(ACK=1, seq=x+1, ack=y+1)，双方进入ESTABLISHED状态

## 必要性证明
第三步ACK的核心目的是防止"历史连接初始化"(RFC 9293 S3.5)：当网络延迟导致旧SYN报文迟到时，若只有两步，服务端会为过期请求分配资源。三次握手确保客户端确认自己仍然需要这条连接。

## 报文格式关键字段
TCP首部(20字节最小)中与握手相关的字段：
- 控制标志位(6bit)：SYN(同步序号)、ACK(确认有效)
- 序号(32bit)：ISN由RFC 6528建议的安全随机算法生成
- 确认号(32bit)：期望收到的下一个字节序号

来源章节 = 第5章运输层 / 谢希仁《计算机网络》第8版
```

# ARP地址解析：从IP到MAC的桥梁

## 实操场景
当主机A(192.168.1.10)要向同一子网的主机B(192.168.1.20)发送数据时，需要通过ARP(RFC 826)获取B的MAC地址。

## 操作步骤
1. 打开Wireshark，设置过滤器：`arp`
2. 在终端执行：`arp -d 192.168.1.20`（清除缓存）
3. 执行：`ping 192.168.1.20`（触发ARP请求）
4. 观察Wireshark捕获：
   - ARP Request（广播）：Who has 192.168.1.20? Tell 192.168.1.10
   - ARP Reply（单播）：192.168.1.20 is at AA:BB:CC:DD:EE:FF
5. 验证：`arp -a` 查看缓存表已更新

## 协议关键点
- ARP请求使用以太网广播(FF:FF:FF:FF:FF:FF)，应答使用单播
- ARP工作在数据链路层（封装在以太网帧中，EtherType=0x0806）
- ARP缓存有TTL机制（Linux默认300秒），超时需重新解析

来源章节 = 第4章网络层 / 谢希仁《计算机网络》第8版
```
