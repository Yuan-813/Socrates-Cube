## 一、项目概述

### 1.1 背景与定位

在高校《计算机网络》课程教学中，传统辅助工具存在三个核心痛点：一是只能判断"对错"，无法告诉学生"为什么错"；二是学习资源千篇一律，无法适配不同认知基础的学生；三是学习路径固定，缺乏对知识图谱前置依赖关系的利用。

**Socrates-Cube**（苏格拉底方块）针对上述问题，构建了一个以苏格拉底式追问为核心交互范式、以多智能体协同为技术底座的自适应学习系统。系统专注于计算机网络领域，通过认知诊断→画像建模→资源生成→路径规划→概念挑战的闭环机制，将"被动答题"升级为"主动认知修复"的学习体验。

### 1.2 系统定位

- **目标用户**：高校计算机网络课程学生（本科/研究生）
- **核心价值**：从"判断对错"到"理解为什么错"，从"通用内容"到"个性化资源"
- **技术路线**：大语言模型（讯飞星火） + 多智能体（6-Agent协同） + 知识图谱（KP-ACU双层） + RAG（三库增强检索）

## 二、核心功能亮点

### 2.1 三层认知诊断（DiagnosisAgent）

系统对学生每条回答执行三层递进分析：
- **L1（表面错误检测）**：识别事实性错误（如"TCP两次握手"）、概念混淆、计算错误等，基于LLM判断 + 关键词规则双重校验
- **L2（根因分析）**：分析错误的深层认知原因，定位缺失的前置知识节点
- **L3（误区模式匹配）**：在150条预定义误解库（23种错误类型）中精准匹配，给出针对性干预策略

三层诊断结果包含10个输出字段（is_correct、confidence、surface_error、error_type、root_causes、missing_prerequisites、pattern、intervention_suggestion、related_node_ids、agent_trace），为后续资源生成和路径规划提供精准依据。

### 2.2 8维动态学习画像（ProfilerAgent）

系统为每位学生维护8个能力维度的实时画像：
| 维度 | 含义 |
|---|---|
| conceptual_understanding | 概念理解深度 |
| protocol_analysis | 协议分析能力 |
| calculation_ability | 计算推导能力 |
| error_diagnosis | 自我纠错能力 |
| system_design | 系统设计思维 |
| knowledge_connection | 知识关联迁移 |
| expression_clarity | 表达清晰程度 |
| self_correction | 自我修正能力 |

画像采用**混合更新策略**：LLM增量校准（每轮对话，解析 -0.2~+0.2 的维度增量）+ 确定性掌握度更新（诊断正确+0.05，诊断错误-0.07）。8维画像值域 [0.1, 1.0]，初始值均为 0.5。

### 2.3 6-Agent 多智能体协同（SSE流式推送）

系统部署6个专业Agent，由OrchestratorAgent统一调度：

| Agent | 职责 | 实现文件 |
|---|---|---|
| OrchestratorAgent | 意图识别、工作流编排、SSE事件发布 | orchestrator.py (217行) |
| DiagnosisAgent | 三层认知诊断 | diagnosis.py (241行) |
| ProfilerAgent | 8维画像动态更新 | profiler.py (158行) |
| RetrieverAgent | 三库向量检索 + 知识图谱查询 | retriever.py (141行) |
| ResourceGeneratorAgent | 三类学习资源生成（doc/exercise/code） | resource_generator.py (244行) |
| PathPlannerAgent | Kahn拓扑排序学习路径规划 | path_planner.py (111行) |

Agent间通过SSE（Server-Sent Events）实现毫秒级事件推送，前端可实时可视化Agent执行链路，包含 agent_start/agent_end/diagnosis/token/resource/path_update/done/error 等事件类型。

### 2.4 知识图谱引导的学习路径规划

PathPlannerAgent基于知识图谱的前置依赖关系，使用**Kahn拓扑排序算法**确定学习顺序：
- 优先识别掌握度低于0.65的薄弱前置知识（find_weak_prerequisites，DFS算法）
- 按章节、难度、节点ID三级排序确定最优学习序列
- 为每个路径节点生成三维推荐理由（图谱前置依赖 / 学生画像诊断 / 掌握度差距）
- 节点状态分4级：completed（≥0.82）/ in_progress / pending / locked

## 三、三大技术创新

### 创新一：三层认知诊断框架（Three-Layer Cognitive Diagnosis）

**解决的问题**：传统AI教学系统只输出"正确/错误"二值结论，无法告知学生"错在哪里"以及"为什么错"。

**技术方案**：
```
L1（表面错误检测）→ LLM语义判断 + 关键词硬规则双重机制
          ↓（检测到错误时）
L2（根因溯源）→ LLM分析缺失的前置知识节点（knowledge_node_ids）
          ↓
L3（误区模式匹配）→ 在150条预定义误解库中向量检索最近邻，识别error_type
          ↓
干预策略输出 → simulation/doc/exercise/follow_up_question/contrast_table
```

**代码实现**：`src/loopse/agents/diagnosis.py`，方法链 `diagnose()` → `_detect_surface_error()` + `_analyze_root_cause()` + `_match_pattern()`

**工程特色**：内置硬规则（"两次握手"自动标记为factual错误），确保高频错误的零误判率；AwaitableDict包装支持同步/异步双重调用模式。

---

### 创新二：混合更新学习画像策略（Hybrid Profile Update Strategy）

**解决的问题**：纯LLM更新画像延迟高（每次都要调用大模型），纯规则更新缺乏语义理解能力。

**技术方案**：两种更新机制并行运行：

**机制A（LLM增量校准）**：
- 每轮对话后，将当前对话内容和诊断结果发送给LLM
- LLM返回8个维度各自的增量值 δ ∈ [-0.2, +0.2]
- 通过 `_parse_delta()` 解析并边界约束后应用

**机制B（确定性掌握度更新）**：
- 诊断结果为正确：`mastery_map[node_id] += 0.05`
- 诊断结果为错误：`mastery_map[node_id] -= 0.07`
- 所有值限制在 [0.0, 1.0] 范围内

**代码实现**：`src/loopse/agents/profiler.py`，核心方法 `update_from_dialogue()` → `_parse_delta()` + `_apply_delta()`

**工程特色**：LLM调用失败时自动降级为纯确定性更新，系统鲁棒性强；mastery_map 动态维护 weak_points（<0.5）和 strong_points（≥0.8）列表。

---

### 创新三：KP-ACU双层知识图谱 + RAG三库增强检索

**解决的问题**：单层知识图谱难以同时支持宏观学习路径规划和微观误解定位两种需求；通用向量检索缺乏领域知识的分层管理。

**技术方案**：

**知识图谱双层建模**：
- **KP层（Knowledge Point，知识概念层）**：粒度较粗的学习概念节点，用于学习路径规划（如"TCP三次握手"、"拥塞控制"）
- **ACU层（Atomic Cognitive Unit，原子认知层）**：细粒度认知单元，与误解库条目精确对应（如"acu_025"对应TCP握手次数误解）

**RAG三库设计**：
| 集合名称 | 用途 | 检索触发条件 |
|---|---|---|
| course_docs | 课程讲义文档片段 | 所有QA问答 |
| protocol_specs | RFC协议规范摘要 | 协议相关问题 |
| misconceptions | 150条误解库全文 | 诊断增强检索 |

**降级机制**：ChromaDB不可用时，自动切换至本地TF-IDF索引（data/vector_db/local_index.json），使用 \(TF\text{-}IDF = \sum_{t}(1+\log tf_t) \cdot (\log\frac{N+1}{df_t+1}+1)\) 计算相关度。

**代码实现**：`src/loopse/kb/knowledge_graph.py`（KnowledgeGraph类）+ `src/loopse/kb/vector_store.py`（VectorStore类）
