# 最终用户操作与部署实施手册 v1.0

> 最后更新：2026-07-13

## 第一章 系统简介

### 1.1 项目定位

Socrates-Cube（苏格拉底方块）是面向《计算机网络》课程的多智能体自适应学习系统，参加软件杯 A3 赛项——AI 赋能教育创新。系统通过 8 个协作智能体为学生提供**苏格拉底式追问、三层认知诊断、个性化资源推荐和学习路径规划**的一体化辅学体验。

### 1.2 核心功能

1. **流式对话**：基于 SSE 的实时流式回复，支持多 Agent 协作过程可视化
2. **三层诊断**：表层错误识别 → 根因溯源 → 误区模式匹配
3. **八维画像**：知识储备、认知风格、学习进度、协议理解、动手能力、常见错误、学习偏好、综合水平
4. **五类资源**：知识文档、练习题、代码示例、思维导图、视频脚本
5. **路径规划**：基于知识图谱拓扑排序的个性化学习路径
6. **协议仿真**：7 种协议场景可视化播放（握手/挥手/滑动窗口/HTTP/DNS/拥塞控制）
7. **可信机制**：越界拦截 + 引用溯源 + 不确定性声明

### 1.3 适用人群

- **学生**：提问概念/流程/计算题，查看诊断、资源和路径推荐
- **助教**：查看诊断标签、Agent 日志，验证系统可解释性
- **教师**：关注知识库来源、误区库质量、验收记录与系统稳定性

### 1.4 八大智能体概览

| Agent | 职责 | 触发条件 |
|-------|------|----------|
| **Orchestrator** | 多 Agent 调度与协作编排 | 每次对话自动触发 |
| **Profiler** | 学生八维画像维护与更新 | 对话时实时更新，每 5 轮 LLM 校准 |
| **Retriever** | 知识库向量检索与查询扩展 | 需要知识支撑时自动触发 |
| **Diagnosis** | 三层递进式认知诊断 | 检测到学生错误时触发 |
| **ResourceGenerator** | 5 类个性化学习资源生成 | 诊断完成后触发 |
| **PathPlanner** | 知识图谱驱动的学习路径规划 | 画像更新后触发 |
| **Challenger** | 苏格拉底式追问出题 | 对话中适时追问 |
| **Simulator** | 7 种协议仿真场景播放 | 用户请求仿真时触发 |

### 2.2 一键启动（推荐）

#### Windows 用户

```bash
# 在项目根目录执行
start.bat
```

一键启动脚本会自动完成：
1. 检查 Python 环境是否就绪
2. 创建虚拟环境（首次运行时）
3. 安装 Python 依赖
4. 复制 `.env.example` → `.env`（首次运行时）
5. 启动后端服务（端口 8000）
6. 安装前端依赖（首次运行时）
7. 启动前端服务（端口 5173）
8. 执行健康检查并输出访问地址

#### Linux/macOS 用户

```bash
chmod +x start.sh
./start.sh
```

#### Mock 模式一键启动

```bash
# Windows
start.bat --mock-mode

# Linux/macOS
./start.sh --mock-mode
```

### 2.3 手动分步启动

如果一键脚本出现异常，可手动分步执行：

**第一步：环境验证**

```bash
cd Socrates-Cube
python scripts/verify_env.py
```

验证脚本会检查：Python 版本、核心依赖包、环境变量配置、知识库索引状态。

可能的报错及解决：
- `Python 版本错误：当前 3.9`：安装 Python 3.10，确认 PATH 优先级
- `缺少以下核心依赖`：执行 `pip install -r requirements.txt`
- `知识库尚未初始化`：执行知识库构建流程（见第二步）

**第二步：后端启动**

```bash
# 1. 创建并激活虚拟环境
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# Windows CMD:
.venv\Scripts\activate.bat
# Linux/macOS:
source .venv/bin/activate

# 2. 安装依赖
pip install -r requirements.txt
# 国内网络推荐使用镜像加速：
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple

# 3. 配置环境变量
copy .env.example .env          # Windows
cp .env.example .env            # Linux/macOS

# 4. 构建知识库（首次部署必须执行）
python scripts/download_knowledge_sources.py   # 下载原始资料
python scripts/ingest_docs.py                  # 清洗入库向量库
python scripts/build_knowledge_base.py         # 构建知识图谱
python scripts/init_db.py                      # 初始化 SQLite 演示数据

# 5. 启动后端服务
uvicorn src.loopse.main:app --reload --host 0.0.0.0 --port 8000
```

常见启动报错：

| 报错信息 | 原因 | 解决方案 |
|----------|------|----------|
| `ModuleNotFoundError: No module named 'fastapi'` | 未安装依赖或未激活虚拟环境 | 激活 venv 后重新 `pip install -r requirements.txt` |
| `Address already in use: 8000` | 端口被占用 | 关闭占用进程或使用 `--port 8001` |
| `UnicodeDecodeError` | Windows 终端编码问题 | 执行 `chcp 65001` 切换为 UTF-8 |
| `aiosqlite not found` | 数据库异步驱动缺失 | `pip install aiosqlite` |
| `.env file not found` | 未创建环境配置 | `copy .env.example .env` |

**第三步：前端启动**

```bash
cd frontend
npm install
npm run dev
# 访问 http://localhost:5173
```

常见启动报错：

| 报错信息 | 原因 | 解决方案 |
|----------|------|----------|
| `npm ERR! ERESOLVE` | 依赖版本冲突 | 删除 `node_modules` 和 `package-lock.json` 后重新 `npm install` |
| `EACCES permission denied` | 权限不足（Linux/macOS） | 使用 `sudo chown -R $USER ~/.npm` 修复权限 |
| `Port 5173 is already in use` | 端口被占用 | 关闭占用进程或在 `vite.config.ts` 中修改 port |
| `vue-tsc error` | TypeScript 类型检查失败 | 仅开发阶段可忽略，使用 `npm run dev` 跳过类型检查 |

**第四步：验证部署**

```bash
# 后端健康检查
curl http://localhost:8000/health
# 期望输出：{"status": "ok"}

# 后端 API 文档
# 浏览器打开：http://localhost:8000/docs

# 前端联通
# 浏览器打开：http://localhost:5173，看到首页
```

## 第三章 核心功能操作指南

### 3.1 对话学习流程

**操作步骤：**

1. **进入对话页面**：打开浏览器访问 `http://localhost:5173`，默认即为对话页面
2. **输入问题**：在底部输入框中输入计算机网络相关问题，支持以下类型：
   - 概念询问：如"什么是TCP三次握手？"
   - 流程追问：如"TCP四次挥手为什么需要TIME_WAIT？"
   - 计算题：如"子网掩码255.255.255.192的主机数"
   - 仿真请求：如"演示三次握手过程"
   - 诊断请求：如"诊断我的理解水平"
3. **查看流式回复**：系统以 SSE 流式方式逐字输出回答，同时右侧面板实时更新
4. **观察多 Agent 协作**：
   - 顶部 AgentStatusBar 显示当前正在工作的 Agent 及其状态
   - Orchestrator → Retriever（检索）→ Diagnosis（诊断）→ Profiler（更新画像）→ ResourceGenerator（生成资源）→ PathPlanner（路径规划）
5. **查看附属面板**：右侧面板包含资源卡片、诊断结果、画像雷达图等信息

**快捷提问入口**：对话页面提供快捷按钮：
- 「概念询问」：什么是TCP三次握手？
- 「仿真请求」：演示三次握手过程
- 「生成题目」：生成协议练习题
- 「能力诊断」：诊断我的理解水平

### 3.2 画像查看与解读

**操作步骤：**

1. **进入画像页面**：点击左侧导航"画像"选项卡
2. **查看八维雷达图**：页面中央显示雷达图，八个维度分别为：
   - 知识储备（Knowledge Base）：整体知识覆盖度
   - 认知风格（Cognitive Style）：学习方式偏好识别
   - 学习进度（Learning Progress）：课程完成度
   - 协议理解（Protocol Understanding）：协议机制理解深度
   - 动手能力（Hands-on Skills）：代码/实操能力
   - 常见错误（Common Mistakes）：典型错误频率（分越高表示错误越少）
   - 学习偏好（Learning Preference）：资源类型倾向
   - 综合水平（Overall Level）：加权综合评估
3. **解读分数**：每个维度 0-100 分
   - 80-100：优秀，已充分掌握
   - 60-79：良好，存在提升空间
   - 40-59：中等，需要针对性加强
   - 0-39：薄弱，建议重点关注
4. **观察更新**：画像随对话自动更新；确定性更新每轮生效，LLM 深度校准每 5 轮触发

### 3.3 协议仿真播放器使用说明

**操作步骤：**

1. **进入仿真页面**：点击左侧导航"仿真"选项卡
2. **选择仿真场景**：从顶部下拉框选择 7 种场景之一
3. **调节仿真参数**（右侧参数面板）：
   - 窗口大小（Window Size）：512~65535 bytes，影响流量控制
   - 往返延迟（RTT）：1~1000 ms，模拟网络延迟
   - 丢包率（Packet Loss）：0~50%，触发重传/拥塞控制
4. **选择参数预设**（可选）：
   - 默认参数：windowSize=4096, RTT=50ms, 丢包率=0%
   - 高延迟网络：windowSize=2048, RTT=300ms, 丢包率=5%
   - 高丢包网络：windowSize=4096, RTT=100ms, 丢包率=20%
   - 受限带宽：windowSize=1024, RTT=200ms, 丢包率=10%
5. **播放动画**：点击"播放"按钮，Canvas 画布上显示报文传输动画
6. **查看报文详情**：点击任意步骤，下方弹出报文详情面板，展示：
   - 发送方/接收方
   - TCP 标志位（SYN/ACK/FIN/PSH等）
   - 序列号与确认号
   - 客户端/服务端当前状态
   - 步骤描述与详细说明
7. **控制播放**：
   - ▶ 播放/暂停：自动步进
   - ⏭ 步进：逐步前进一帧
   - ⏮ 后退：回退一帧
   - 🔄 重置：回到初始状态
   - 速度调节：调整动画播放速度

#### 3.3.1 场景一：TCP 三次握手

| 步骤 | 方向 | 标志位 | 序列号/确认号 | 状态变迁 | 说明 |
|------|------|--------|-------------|----------|------|
| 1 | Client → Server | SYN | seq=100, ack=0 | Client: SYN_SENT, Server: LISTEN | 客户端选择 ISN=100，发起连接 |
| 2 | Server → Client | SYN+ACK | seq=200, ack=101 | Client: SYN_SENT, Server: SYN_RCVD | 服务端分配 ISN=200，确认客户端 |
| 3 | Client → Server | ACK | seq=101, ack=201 | Client: ESTABLISHED, Server: ESTABLISHED | 连接建立完成 |

**教学要点**：观察 ISN 随机性、确认号=对端序列号+1 的规律、状态机迁移过程。

#### 3.3.2 场景二：TCP 四次挥手

| 步骤 | 方向 | 标志位 | 序列号/确认号 | 状态变迁 | 说明 |
|------|------|--------|-------------|----------|------|
| 1 | Client → Server | FIN+ACK | seq=500, ack=400 | Client: FIN_WAIT_1, Server: ESTABLISHED | 客户端主动关闭 |
| 2 | Server → Client | ACK | seq=400, ack=501 | Client: FIN_WAIT_2, Server: CLOSE_WAIT | 服务端确认 |
| 3 | Server → Client | FIN+ACK | seq=401, ack=501 | Client: TIME_WAIT, Server: LAST_ACK | 服务端也关闭 |
| 4 | Client → Server | ACK | seq=501, ack=402 | Client: CLOSED, Server: CLOSED | 2MSL 后完全关闭 |

**教学要点**：理解半关闭状态、TIME_WAIT 存在意义（防止延迟报文）、2MSL 等待时长。

#### 3.3.3 场景三：TCP 滑动窗口

展示连续数据传输与流量控制过程，包含 6 个步骤：窗口通告 → 连续发送多段 → 累积确认 → 窗口调整 → 继续发送 → 全量确认。

**参数调节建议**：
- 增大窗口大小（如 65535）：观察发送方可连续发送更多数据段
- 减小窗口大小（如 1024）：观察每轮发送数据量受限
- 增加 RTT：观察窗口利用率下降

#### 3.3.4 场景四：HTTP 请求响应

展示完整 HTTP 通信流程（7 步）：TCP 三次握手 → HTTP GET 请求 → 服务端 ACK → HTTP 200 响应 → 客户端 ACK。

**教学要点**：应用层协议依赖传输层连接、HTTP 报文承载在 TCP 数据段中、请求/响应模型。

#### 3.3.5 场景五：HTTP 分层封装

展示数据从应用层到物理层的逐层封装过程（6 步）：

1. 应用层：HTTP 请求报文（Method + URL + Headers + Body）
2. 传输层：添加 TCP 头部（源端口:49152 → 目的端口:80）
3. 网络层：添加 IP 头部（源IP → 目的IP，TTL=64）
4. 数据链路层：添加以太网帧头（源MAC → 目的MAC）
5. 物理层：转换为比特流
6. 服务端逐层解封装

**教学要点**：PDU 命名变化（报文→段→包→帧→比特）、每层头部包含的关键字段。

#### 3.3.6 场景六：DNS 解析

展示域名解析的递归+迭代查询过程（5 步）：

1. 客户端向本地 DNS 发起递归查询
2. 本地 DNS 向根服务器迭代查询 → 获得 .com TLD 地址
3. 本地 DNS 向 .com TLD 查询 → 获得权威 DNS 地址
4. 本地 DNS 向权威 DNS 查询 → 获得目标 IP
5. 本地 DNS 返回结果给客户端（附带 TTL 缓存信息）

**教学要点**：递归查询与迭代查询的区别、DNS 层次结构、TTL 缓存机制。

#### 3.3.7 场景七：拥塞控制（基础版）

展示 TCP 拥塞窗口动态变化过程（6 步）：

1. 慢启动：cwnd=1 MSS，指数增长
2. cwnd 翻倍：1→2→4 MSS
3. 达到 ssthresh：进入拥塞避免
4. 拥塞避免：线性增长 +1/RTT
5. 检测到丢包：ssthresh=cwnd/2，cwnd 减半
6. 重新进入拥塞避免，线性增长

**参数调节建议**：
- 设置高丢包率（20%）：观察频繁的 cwnd 减半与重传
- 设置高延迟（300ms）：观察慢启动阶段持续时间更长

### 3.5 诊断面板使用说明

**操作步骤：**

1. **触发诊断**：在对话中输入包含错误理解的回答（如"HTTP 直接基于 IP 层传输"）
2. **查看诊断面板**：诊断面板自动展示在对话右侧
3. **解读三层结果**：

#### 第一层：表层错误识别

- **显示内容**：错误类型图标、颜色编码、置信度仪表盘
- **错误类型分类**（7 种）：
  - 流程遗漏：遗漏关键步骤（如三次握手只说了两步）
  - 层级错位：将某层概念误归到其他层
  - 概念混淆：混淆相近概念（如 TCP/UDP 特征互换）
  - 参数错误：关键参数值记错
  - 因果颠倒：因果关系理解反向
  - 范围越界：将正确结论过度泛化
  - 术语误用：使用了错误的专业术语
- **置信度颜色编码**：
  - 🟢 绿色（≥85%）：系统高度确信诊断准确
  - 🔵 蓝色（70-84%）：诊断较为可信
  - 🟡 黄色（50-69%）：诊断供参考，可能有偏差
  - 🔴 红色（<50%）：诊断不确定，需更多上下文

#### 第二层：根因溯源分析

- **显示内容**：树形结构展示薄弱知识点
- **解读方法**：
  - 根节点：当前错误表现
  - 子节点：导致错误的底层知识缺失
  - 标注内容：缺失的前置知识点 ID 和知识图谱位置
  - 多根因排序：按影响程度从高到低排列
- **典型示例**：学生说"TCP 不需要握手"→ 根因：1）连接导向概念未建立；2）TCP vs UDP 区别未区分

#### 第三层：误区模式匹配

- **显示内容**：模式类型标签（悬停查看模式说明）+ 干预建议
- **7 种误区模式**：
  - 协议混淆型：将不同协议特征互相张冠李戴
  - 层级穿越型：跨层理解出现错位
  - 流程省略型：对多步流程的关键步骤存在遗漏
  - 参数记忆型：对关键数值/范围记忆错误
  - 因果误解型：对因果或时序关系理解错误
  - 过度泛化型：将局部规律错误推广
  - 术语混用型：形近/义近术语使用错误
- **干预建议示例**：仿真纠偏、对比题练习、关键字段标注、步骤拆解练习

## 第五章 常见问题 FAQ

### Q1：启动后端报错"ModuleNotFoundError"
**A**：确认已激活虚拟环境（`.venv\Scripts\activate.bat`）并安装依赖（`pip install -r requirements.txt`）。若仍报错，检查是否在项目根目录下执行。

### Q2：前端访问 localhost:5173 显示空白
**A**：检查后端是否已启动（`curl http://localhost:8000/health`），若未启动先启动后端。同时确认浏览器控制台是否有 CORS 或 Network 错误。

### Q3：诊断结果不显示
**A**：诊断仅在检测到学生回答错误时触发。输入明显错误的回答（如"HTTP直接基于IP"）可触发诊断。对话首轮通常不触发诊断。

### Q4：仿真动画卡顿
**A**：检查浏览器是否支持 Canvas 2D。推荐使用 Chrome 最新版，关闭其他占用 GPU 的标签页。若仍卡顿，降低播放速度。

### Q5：资源生成失败
**A**：检查讯飞 API Key 是否配置正确。未配置时系统自动进入 Mock 模式，会返回预设资源。若 Mock 模式也失败，检查 `frontend/public/mock/resources_mock.json` 文件是否存在。

### Q6：画像雷达图不更新
**A**：画像随对话轮次自动更新。确定性更新每轮生效，LLM 校准每 5 轮触发一次。首次使用时需要至少 2-3 轮对话才能看到明显变化。

### Q7：如何切换学生用户
**A**：当前默认用户为 student-001。可在对话请求中修改 user_id 参数切换用户。Mock 模式预设了 3 个用户：student-001（初学者）、student-002（进阶）、student-003（高手）。

### Q8：ChromaDB 安装失败
**A**：ChromaDB 为可选依赖。安装失败时系统自动降级到本地 JSON 索引模式（`data/vector_db/local_index.json`）。常见失败原因：C++ 编译环境缺失（Windows 需 Visual Studio Build Tools）。

### Q9：路径推荐理由没有三维
**A**：三维理由需要画像和诊断数据支撑。多轮对话产生诊断结果后，路径规划会自动附加三维理由（图谱依赖 + 诊断结果 + 认知风格）。

### Q10：如何查看完整 Agent 调用链
**A**：进入"日志"页面，或访问后端 Swagger 文档（`http://localhost:8000/docs`）查看 agent_logs API。每次对话的完整调用链包含调用顺序、耗时和返回结果。

### Q11：一键启动脚本无法运行
**A**：确保 Python 3.10+ 和 Node.js 18+ 已安装并加入 PATH。首次运行会自动创建虚拟环境和安装依赖，若网络较慢可能需要等待 2-5 分钟。

### Q12：Mock 模式和正常模式区别
**A**：正常模式调用讯飞星火 API，回复更真实、更个性化；Mock 模式使用预设数据，断网也可完整演示全部功能流程。演示效果方面无本质差异。

### Q13：pip install 下载速度极慢
**A**：使用国内镜像源加速：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple`。也可配置全局镜像：`pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple`。

### Q14：Windows PowerShell 中激活虚拟环境报错"禁止运行脚本"
**A**：需要修改执行策略。以管理员身份运行 PowerShell 执行：`Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser`。或改用 CMD 执行 `.venv\Scripts\activate.bat`。

### Q15：前端构建时 TypeScript 类型报错
**A**：开发模式（`npm run dev`）不执行类型检查，可正常运行。仅 `npm run build` 会触发 `vue-tsc` 检查。如需跳过类型检查直接构建，可执行：`npx vite build`。

### Q16：数据库 edu_agent.db 报错"database is locked"
**A**：关闭所有访问数据库的进程（包括 DB 可视化工具），然后重启后端服务。SQLite 不支持高并发写入，确保同时只有一个服务实例运行。

### Q17：仿真场景播放到一半报错
**A**：检查浏览器是否处于标签页休眠状态。Chrome 可能会在后台暂停 Canvas 渲染。保持仿真页面在前台运行。若仍有问题，点击"重置"后重新播放。

### Q18：知识库检索结果不准确
**A**：确认知识库已完整构建（执行 `python scripts/verify_env.py` 检查）。若 course_docs < 30 或 misconceptions < 20，需重新执行 `python scripts/ingest_docs.py --reset` 重建索引。

### Q19：如何清空对话历史重新开始
**A**：方法一：使用快捷键 `Ctrl+Shift+C` 清空当前对话。方法二：刷新浏览器页面。方法三：切换用户 ID 开始新会话。

### Q20：后端 API 文档在哪里
**A**：后端基于 FastAPI 自动生成 Swagger 文档，访问 `http://localhost:8000/docs`（Swagger UI）或 `http://localhost:8000/redoc`（ReDoc 格式）。

### Q21：前端如何切换 Mock/正常模式
**A**：停止当前前端服务，使用 `npm run dev:mock` 启动 Mock 模式，或 `npm run dev` 启动正常模式。前端通过 Vite 的 `--mode mock` 参数读取 `.env.mock` 配置文件。

### Q22：诊断置信度低于50%是什么意思
**A**：说明系统对当前诊断结果不确定，可能是学生回答模糊或上下文不足。建议学生更详细地表述理解，多轮对话后诊断准确度会提高。

## 第六章 环境排障指南

### 6.1 Python 环境问题

| 问题 | 解决方案 |
|------|----------|
| Python 版本过低 | 安装 Python 3.10+，确认 `python --version` 输出 |
| pip 安装超时 | 使用国内镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| venv 创建失败 | 确认 Python 路径已加入系统 PATH，或使用 `python -m ensurepip` 修复 |
| 多版本 Python 冲突 | Windows 使用 `py -3.10 -m venv .venv` 指定版本 |
| SSL 证书错误 | pip 添加 `--trusted-host pypi.org --trusted-host pypi.tuna.tsinghua.edu.cn` |

### 6.2 Node.js 环境问题

| 问题 | 解决方案 |
|------|----------|
| npm install 报错 | 删除 node_modules 和 package-lock.json 后重试 |
| 端口 5173 被占用 | 关闭占用进程或修改 vite.config.ts 中的 port |
| 构建失败 | 确认 Node.js 18+，运行 `node -v` 检查 |
| npm 权限问题（Linux） | `sudo chown -R $USER ~/.npm` |
| node-gyp 编译失败 | Windows 安装 `npm install -g windows-build-tools` |

### 6.3 数据库问题

| 问题 | 解决方案 |
|------|----------|
| edu_agent.db 锁定 | 关闭所有访问数据库的进程后重试 |
| 表不存在 | 执行 `python scripts/init_db.py` 重新初始化 |
| 数据库文件损坏 | 删除 `edu_agent.db` 后重新执行 `python scripts/init_db.py` |

### 6.4 API 连接问题

| 问题 | 解决方案 |
|------|----------|
| 讯飞 API 超时 | 检查网络或切换到 Mock 模式 |
| SSE 连接中断 | 刷新前端页面，检查后端服务是否存活 |
| CORS 错误 | 确认后端已配置跨域中间件，前端 API 地址正确 |
| 403 Forbidden | 检查讯飞 API Key 是否过期或额度用尽 |

### 6.5 知识库问题

| 问题 | 解决方案 |
|------|----------|
| 检索无结果 | 执行 `python scripts/verify_env.py` 检查知识库数据量 |
| ingest_docs 报错 | 确认 `data/cleaned/` 目录下有 `.md` 文件 |
| ChromaDB 连接失败 | 系统自动降级到 JSON 索引，不影响基本功能 |

# 最终用户操作与部署实施手册 v1.0

## 第一章 系统简介

### 1.1 项目定位

Socrates-Cube（苏格拉底方块）是面向《计算机网络》课程的多智能体自适应学习系统，参加软件杯 A3 赛项——AI 赋能教育创新。系统通过 8 个协作智能体为学生提供**苏格拉底式追问、三层认知诊断、个性化资源推荐和学习路径规划**的一体化辅学体验。

### 1.2 核心功能

1. **流式对话**：基于 SSE 的实时流式回复，支持多 Agent 协作过程可视化
2. **三层诊断**：表层错误识别 → 根因溯源 → 误区模式匹配
3. **八维画像**：知识储备、认知风格、学习进度、协议理解、动手能力、常见错误、学习偏好、综合水平
4. **五类资源**：知识文档、练习题、代码示例、思维导图、视频脚本
5. **路径规划**：基于知识图谱拓扑排序的个性化学习路径
6. **协议仿真**：7 种协议场景可视化播放（握手/挥手/滑动窗口/HTTP/DNS/拥塞控制）
7. **可信机制**：越界拦截 + 引用溯源 + 不确定性声明

### 1.3 适用人群

- **学生**：提问概念/流程/计算题，查看诊断、资源和路径推荐
- **助教**：查看诊断标签、Agent 日志，验证系统可解释性
- **教师**：关注知识库来源、误区库质量、验收记录与系统稳定性

### 4.1 何时使用离线模式

前端 Mock 模式会：
- 拦截所有 API 请求并返回本地 JSON 数据
- 使用 setInterval 模拟 SSE 流式输出效果
- 全链路 0 报错，适合离线演示

## 第五章 常见问题 FAQ

### Q1：启动后端报错“ModuleNotFoundError”
**A**：确认已激活虚拟环境（`.venv\Scripts\activate.bat`）并安装依赖（`pip install -r requirements.txt`）。

### Q2：前端访问 localhost:5173 显示空白
**A**：检查后端是否已启动（`curl http://localhost:8000/health`），若未启动先启动后端。

### Q3：诊断结果不显示
**A**：诊断仅在检测到学生回答错误时触发。输入明显错误的回答（如“HTTP直接基于IP”）可触发诊断。

### Q4：仿真动画卡顿
**A**：检查浏览器是否支持 Canvas 2D。推荐使用 Chrome 最新版，关闭其他占用 GPU 的标签页。

### Q5：资源生成失败
**A**：检查讯飞 API Key 是否配置正确。未配置时系统自动进入 Mock 模式，会返回预设资源。

### Q6：画像雷达图不更新
**A**：画像随对话轮次自动更新。确定性更新每轮生效，LLM 校准每 5 轮触发一次。

### Q7：如何切换学生用户
**A**：当前默认用户为 student-001。可在对话请求中修改 user_id 参数切换用户。

### Q8：ChromaDB 安装失败
**A**：ChromaDB 为可选依赖。安装失败时系统自动降级到本地 JSON 索引模式（`data/vector_db/local_index.json`）。

### Q9：路径推荐理由没有三维
**A**：三维理由需要画像和诊断数据支撑。多轮对话产生诊断结果后，路径规划会自动附加三维理由。

### Q10：如何查看完整 Agent 调用链
**A**：进入“日志”页面，或访问后端 Swagger 文档（`http://localhost:8000/docs`）查看 agent_logs API。

### Q11：一键启动脚本无法运行
**A**：确保 Python 3.10+ 和 Node.js 18+ 已安装。首次运行会自动创建虚拟环境和安装依赖。

### Q12：Mock 模式和正常模式区别
**A**：正常模式调用讯飞星火 API，回复更真实；Mock 模式使用预设数据，断网也可完整演示。

## 第六章 环境排障指南

### 6.1 Python 环境问题

| 问题 | 解决方案 |
|------|----------|
| Python 版本过低 | 安装 Python 3.10+ |
| pip 安装超时 | 使用国内镜像：`pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple` |
| venv 创建失败 | 确认 Python 路径已加入系统 PATH |

### 6.2 Node.js 环境问题

| 问题 | 解决方案 |
|------|----------|
| npm install 报错 | 删除 node_modules 和 package-lock.json 后重试 |
| 端口 5173 被占用 | 关闭占用进程或修改 vite.config.ts 中的 port |
| 构建失败 | 确认 Node.js 18+，运行 `node -v` 检查 |

### 6.3 数据库问题

| 问题 | 解决方案 |
|------|----------|
| edu_agent.db 锁定 | 关闭所有访问数据库的进程后重试 |
| 表不存在 | 执行 `python scripts/init_db.py` 重新初始化 |

### 6.4 API 连接问题

| 问题 | 解决方案 |
|------|----------|
| 讯飞 API 超时 | 检查网络或切换到 Mock 模式 |
| SSE 连接中断 | 刷新前端页面，检查后端服务是否存活 |
