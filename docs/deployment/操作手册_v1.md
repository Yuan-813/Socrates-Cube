## 2 系统概述

### 2.1 系统定位

Socrates-Cube 是面向《计算机网络》课程的多智能体自适应学习系统，通过 8 个协作智能体实现"苏格拉底式问答 + 三层认知诊断 + 个性化资源推荐 + 知识图谱路径规划"的一体化辅学体验。系统能够识别学生的认知误区、生成个性化学习资源，并依据知识图谱为每位学生规划专属的学习路径。

### 2.2 核心功能概览

| 功能模块 | 功能说明 | 相关 Agent |
|---------|---------|-----------|
| 智能对话 | SSE 流式问答，支持多 Agent 协作可视化 | Orchestrator + Retriever |
| 认知诊断 | 三层递进诊断：表层错误→根因溯源→误区模式 | DiagnosisAgent |
| 学习画像 | 八维画像（知识储备/认知风格等）实时更新 | ProfilerAgent |
| 个性化资源 | 自动生成五类学习资源（文档/题/代码/导图/脚本）| ResourceGeneratorAgent |
| 路径规划 | 基于知识图谱 Kahn 拓扑排序的学习路径 | PathPlannerAgent |
| 协议仿真 | 7 种协议场景 Canvas 动画（TCP/HTTP/DNS 等）| SimulatorAgent |
| 概念挑战 | 苏格拉底式追问与题库练习 | ChallengerAgent |
| 可信机制 | 域外拦截 + 引用溯源 + 不确定性声明 | TrustMechanism |

### 2.3 用户角色与权限

| 角色 | 典型操作 | 说明 |
|------|---------|------|
| 学生 | 对话提问、查看诊断/画像/资源/路径、仿真观看 | 主要使用角色 |
| 助教/教师 | 查看 Agent 日志、验证系统可解释性 | 监督与验收角色 |
| 运维人员 | 环境部署、知识库重建、服务监控 | 管理角色 |

### 2.4 八大智能体职责

| Agent 名称 | 中文名 | 职责 | 触发条件 |
|-----------|--------|------|---------|
| OrchestratorAgent | 编排者 | 多 Agent 调度与协作编排 | 每次对话自动触发 |
| ProfilerAgent | 画像器 | 学生八维画像维护与更新 | 对话时实时更新 |
| RetrieverAgent | 检索器 | 知识库向量检索与查询扩展 | 需要知识支撑时 |
| DiagnosisAgent | 诊断器 | 三层递进式认知诊断 | 检测到学生错误时 |
| ResourceGeneratorAgent | 资源生成器 | 五类个性化学习资源生成 | 诊断完成后 |
| PathPlannerAgent | 路径规划器 | 知识图谱驱动的学习路径规划 | 画像更新后 |
| ChallengerAgent | 追问器 | 苏格拉底式追问出题 | 对话中适时追问 |
| SimulatorAgent | 仿真器 | 七种协议仿真场景播放 | 用户请求仿真时 |

## 3 安装与部署

### 3.1 运行环境要求

#### 3.1.1 硬件要求

| 项目 | 最低配置 | 推荐配置 |
|------|---------|---------|

| 内存 | 4 GB | 8 GB+ |
| 磁盘空间 | 3 GB 可用 | 8 GB+ |
| 网络 | 无（支持 Mock 离线模式）| 有网络（调用讯飞 API）|

#### 3.1.2 软件依赖

| 依赖项 | 要求版本 | 必需 | 验证命令 |
|--------|---------|------|---------|
| Python | 3.10+（已在 3.12.7 验证）| ✅ 必需 | `python --version` |
| pip | 23.0+ | ✅ 必需 | `pip --version` |
| Node.js | 18.0+ | ✅ 必需 | `node -v` |
| npm | 9.0+ | ✅ 必需 | `npm -v` |
| Git | 2.30+ | 推荐 | `git --version` |
| Chrome / Edge | 90+ | 推荐 | — |
| 讯飞星火 API Key | — | 可选 | — |

> **⚠️ 注意**：系统实际运行环境使用 Python 3.12.7 验证。若系统为 Python 3.10，需确认 pip 版本 ≥ 23.0（可通过 `pip install --upgrade pip` 升级）。

### 3.2 快速启动（推荐）

#### Windows 用户

```bat
:: 在项目根目录下执行
start.bat
```

一键启动脚本将自动完成：
1. 检查 Python / Node.js 环境
2. 创建 Python 虚拟环境（`.venv`，首次运行时）
3. 安装后端依赖（`pip install -r requirements.txt`）
4. 复制 `.env.example` → `.env`（首次运行时）
5. 启动后端服务（端口 8000）
6. 安装前端依赖（`npm install`，首次运行时）
7. 启动前端服务（端口 5173）
8. 执行健康检查并输出访问地址

#### Linux / macOS 用户

```bash
chmod +x start.sh
./start.sh
```

#### Mock 离线模式一键启动

```bat
:: Windows
start.bat --mock-mode

:: Linux/macOS
./start.sh --mock-mode
```

### 3.3 手动分步部署

当一键脚本出现异常时，按如下步骤手动部署。

#### 第一步：后端环境准备

```bat
:: 进入项目根目录
cd Socrates-Cube

:: 创建并激活 Python 虚拟环境
python -m venv .venv

:: Windows PowerShell 激活
.venv\Scripts\Activate.ps1

:: Windows CMD 激活
.venv\Scripts\activate.bat

:: Linux/macOS 激活
:: source .venv/bin/activate

:: 安装后端依赖
pip install -r requirements.txt

:: 国内网络推荐使用镜像加速
pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
```

#### 第二步：环境变量配置

```bat
:: Windows
copy .env.example .env

:: Linux/macOS
cp .env.example .env
```

按需编辑 `.env` 文件（详见 §3.4）。

#### 第三步：知识库初始化（首次部署必须）

```bash
python scripts/download_knowledge_sources.py   # 下载原始知识资料
python scripts/ingest_docs.py                  # 清洗文档并入向量库
python scripts/build_knowledge_base.py         # 构建知识图谱
python scripts/init_db.py                      # 初始化 SQLite 演示数据
```

> **[可选]** 若知识库已存在（`data/vector_db/local_index.json` 和 `data/knowledge_graph.json`），可跳过此步骤。

#### 第四步：启动后端服务

```bash
uvicorn src.loopse.main:app --reload --host 0.0.0.0 --port 8000
```

#### 第五步：启动前端服务

```bash
cd frontend
npm install
npm run dev
# 访问 http://localhost:5173
```

### 3.4 API Key 配置

编辑项目根目录的 `.env` 文件，填入讯飞星火大模型凭据：

```env
# 讯飞星火大模型配置
SPARK_APP_ID=your_app_id
SPARK_API_SECRET=your_api_secret
SPARK_API_KEY=your_api_key

# 或使用 XUNFEI 前缀（二选一即可）
XUNFEI_APP_ID=your_app_id
XUNFEI_API_KEY=your_api_key
XUNFEI_API_SECRET=your_api_secret
```

未配置时系统自动进入 Mock LLM 模式，所有功能可正常演示。

**验证配置生效：**

```bash
python scripts/verify_env.py
# 输出 "[OK] 讯飞 API Key 已配置" 表示生效
```

### 3.5 知识库健康检查

| 知识库集合 | 最低文档数 | 说明 |
|-----------|-----------|------|
| course_docs | ≥ 30 | 计算机网络课程章节文档 |

## 5 核心功能操作说明

### 5.1 智能对话

**操作步骤：**

1. 点击左侧导航"对话"进入 `/chat` 页面；
2. 在底部输入框输入问题，支持以下类型：

   | 提问类型 | 示例 |
   |---------|------|
   | 概念询问 | "什么是 TCP 三次握手？" |
   | 流程追问 | "TCP 四次挥手为什么需要 TIME_WAIT？" |
   | 计算题 | "子网掩码 255.255.255.192 的主机数是多少？" |
   | 仿真请求 | "演示 TCP 三次握手过程" |
   | 能力诊断 | "诊断我对 TCP 拥塞控制的理解" |

3. 系统以 SSE 流式方式逐字输出回答，同时右侧面板实时更新；
4. 顶部 AgentStatusBar 展示当前活跃的 Agent 及其状态；
5. 页面底部快捷按钮提供常用提问模板。

**多 Agent 协作流程说明：**

```
用户输入 → OrchestratorAgent（意图分类+域外过滤）
    → RetrieverAgent（三库知识检索）
    → DiagnosisAgent（三层认知诊断，仅当检测到错误时）
    → LLM 流式生成回复（SSE token 事件流）
    → ProfilerAgent（八维画像更新）
    → ResourceGeneratorAgent（五类资源生成）
    → PathPlannerAgent（学习路径重规划）
    → SSE done 事件，前端完成渲染
```

### 5.2 认知诊断面板

当系统检测到学生回答包含错误时，右侧面板自动展开三层诊断结果。

#### 第一层：表层错误识别

- 错误类型图标 + 颜色编码 + 置信度仪表盘；
- 七种错误类型：流程遗漏、层级错位、概念混淆、参数错误、因果颠倒、范围越界、术语误用；
- 置信度颜色编码：

  | 颜色 | 置信度范围 | 含义 |
  |------|-----------|------|
  | 🟢 绿色 | ≥ 85% | 系统高度确信诊断准确 |
  | 🔵 蓝色 | 70–84% | 诊断较为可信 |
  | 🟡 黄色 | 50–69% | 诊断供参考，存在偏差可能 |
  | 🔴 红色 | < 50% | 诊断不确定，需补充上下文 |

#### 第二层：根因溯源分析

- 树形结构展示薄弱知识点及其前置依赖关系；
- 标注缺失的知识点 ID 与知识图谱位置；
- 多根因按影响程度从高到低排列。

**示例**：学生输入"TCP 不需要握手" → 根因分析结果：
1. "连接导向"概念未建立（影响度 0.9）
2. TCP 与 UDP 区别未区分（影响度 0.7）

#### 第三层：误区模式匹配

- 七种误区模式类型（悬停标签可查看模式说明）；
- 配套干预建议（仿真纠偏/对比题练习/步骤拆解等）。

**进入诊断详情页：** 点击左侧导航"诊断"，查看历史诊断记录和完整三层结构。

### 5.3 学习画像（八维雷达图）

**操作步骤：**

1. 点击左侧导航"画像"进入 `/profile` 页面；
2. 页面中央显示八维雷达图，维度说明如下：

   | 维度 | 说明 | 更新方式 |
   |------|------|---------|
   | 知识储备 | 整体知识覆盖度 | 每轮对话确定性更新 |
   | 认知风格 | 学习方式偏好识别 | 长期行为统计 |
   | 学习进度 | 课程知识点完成度 | 路径规划联动 |
   | 协议理解 | 协议机制理解深度 | 诊断结果驱动 |
   | 动手能力 | 代码/实操能力评估 | 资源使用记录 |
   | 常见错误 | 典型错误频率（越高表示错误越少）| 诊断历史统计 |
   | 学习偏好 | 资源类型倾向 | 使用行为分析 |
   | 综合水平 | 加权综合评估 | 每 5 轮 LLM 全量校准 |

3. 评分解读：0–39 薄弱；40–59 中等；60–79 良好；80–100 优秀；
4. 画像随对话自动更新（确定性增量每轮生效，LLM 全量校准每 5 轮触发）。

### 5.4 个性化学习资源

**操作步骤：**

1. 资源生成后自动展示在对话页面右侧面板，或点击"资源"进入 `/resources` 页面；
2. 通过 Tab 标签切换五类资源：

   | 资源类型 | 说明 | 适合学习者 |
   |---------|------|-----------|
   | 知识文档（Doc）| 结构化的知识点解释文档 | 阅读型 |
   | 练习题（Exercise）| 选择/填空/简答题 | 刷题型 |
   | 代码示例（Code）| Python/C 网络编程示例 | 动手型 |
   | 思维导图（MindMap）| Mermaid 格式知识结构图 | 视觉型 |
   | 视频脚本（Script）| 分镜+解说词，适合翻转课堂 | 视听型 |

3. 手动触发资源生成：在对话中输入"给我生成练习题"或"生成代码示例"；
4. 每类资源根据学生认知风格自动调整内容形态。

### 5.5 学习路径规划

**操作步骤：**

1. 在对话中输入"我接下来该学什么"或"推荐学习路径"触发路径规划；
2. 点击左侧导航"路径"进入 `/path` 页面；
3. 页面显示学习路径时间线，每个节点包含：
   - 节点标题（如"TCP 连接管理"）
   - 状态标识：✅ 已完成 / 🔵 当前学习 / ⏳ 待学习 / 🔒 未解锁
   - 预估学习时间（分钟）
4. 点击节点展开三维推荐理由：
   - **图谱依赖**：该知识点在知识图谱中的前置关系（Kahn 拓扑排序结果）
   - **诊断结果**：基于三层诊断识别出的薄弱点
   - **认知风格**：基于学生画像的资源形式推荐
5. 顶部进度条显示"已完成节点/总节点"与预估总学习时间。

### 5.6 协议仿真实验室

**操作步骤：**

1. 点击左侧导航"仿真"进入 `/simulator` 页面；
2. 从顶部下拉框选择七种仿真场景之一：

   | 场景编号 | 场景名称 | 教学要点 |
   |---------|---------|---------|
   | 场景一 | TCP 三次握手 | ISN 随机性、状态机迁移 |
   | 场景二 | TCP 四次挥手 | 半关闭状态、TIME_WAIT 意义 |
   | 场景三 | TCP 滑动窗口 | 流量控制、窗口利用率 |
   | 场景四 | HTTP 请求响应 | 应用层依赖传输层的实现 |
   | 场景五 | HTTP 分层封装 | PDU 逐层封装/解封装 |
   | 场景六 | DNS 解析 | 递归查询与迭代查询的区别 |
   | 场景七 | 拥塞控制 | 慢启动/拥塞避免/cwnd 变化 |

3. 在右侧参数面板调节仿真参数：
   - 窗口大小（512–65535 bytes）
   - 往返延迟 RTT（1–1000 ms）
   - 丢包率（0–50%）
4. 点击"播放"按钮启动 Canvas 动画；
5. 点击任意步骤查看报文详情（标志位/序列号/状态变迁/步骤说明）；
6. 播放控制按钮：▶ 播放/暂停 | ⏭ 步进 | ⏮ 后退 | 🔄 重置 | 速度调节。

**参数预设说明：**

| 预设名称 | 窗口大小 | RTT | 丢包率 | 适合演示场景 |
|---------|---------|-----|-------|------------|
| 默认参数 | 4096 bytes | 50 ms | 0% | 正常传输流程 |
| 高延迟网络 | 2048 bytes | 300 ms | 5% | 慢启动拉长效果 |
| 高丢包网络 | 4096 bytes | 100 ms | 20% | 频繁重传演示 |
| 受限带宽 | 1024 bytes | 200 ms | 10% | 窗口受限场景 |

### 5.7 概念挑战与题库

## 7 常见问题与故障排除

### 7.1 安装部署问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| `ModuleNotFoundError: No module named 'fastapi'` | 未激活虚拟环境或未安装依赖 | 激活 `.venv` 后执行 `pip install -r requirements.txt` |
| `pip install` 超时 | 网络问题 | 添加 `-i https://pypi.tuna.tsinghua.edu.cn/simple` 使用镜像 |
| `Address already in use: 8000` | 端口被占用 | 关闭占用进程或使用 `--port 8001` |
| `UnicodeDecodeError` | Windows 终端编码问题 | 执行 `chcp 65001` 切换 UTF-8 |
| PowerShell 报"禁止运行脚本" | 执行策略限制 | 以管理员身份执行：`Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` |
| `npm ERR! ERESOLVE` | 前端依赖版本冲突 | 删除 `node_modules` 和 `package-lock.json` 后重新 `npm install` |
| `ChromaDB` 安装失败 | 缺少 C++ 编译器 | 系统自动降级至本地 JSON 索引，功能不受影响 |

### 7.2 功能使用问题

| 问题 | 解决方案 |
|------|---------|
| 诊断结果不显示 | 诊断仅在检测到错误时触发，请输入包含错误理解的回答（如"TCP只需两次握手"）|
| 画像雷达图不更新 | 首次使用需 2–3 轮对话，LLM 全量校准每 5 轮触发一次 |
| 资源生成失败 | 检查 API Key 配置；未配置时 Mock 模式会返回预设资源 |
| 路径推荐无三维理由 | 需要诊断数据支撑，多轮对话产生诊断结果后自动附加 |
| 前端显示空白 | 先确认后端已启动：`curl http://localhost:8000/health` |
| 对话无响应 | 检查后端 uvicorn 进程是否存活，必要时重启服务 |

### 7.3 性能与显示问题

| 问题 | 解决方案 |
|------|---------|
| 仿真动画卡顿 | 使用 Chrome 最新版；关闭其他占用 GPU 的标签页；降低播放速度 |
| SSE 流式输出中断 | 刷新前端页面，检查后端 uvicorn 进程；确认防火墙未拦截 8000 端口 |
| 前端 TypeScript 类型报错 | 开发模式不执行类型检查，可正常运行；如需跳过构建检查执行 `npx vite build` |

### 7.4 数据库与知识库问题

| 问题 | 解决方案 |
|------|---------|
| `database is locked` | 关闭所有访问 `edu_agent.db` 的进程后重启服务 |
| 表不存在 | 执行 `python scripts/init_db.py` 重新初始化 |
| 知识库检索无结果 | 执行 `python scripts/verify_env.py` 检查数据量，必要时重建 |
| ChromaDB 连接失败 | 系统已自动降级至 JSON 索引，不影响核心功能 |
