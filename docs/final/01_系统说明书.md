# Socrates Cube 系统说明书

**系统名称**：Socrates Cube（苏格拉底方块）——多智能体自适应计算机网络学习系统

**版本**：v1.0.0

**参赛信息**：第十五届"中国软件杯"大学生软件设计大赛 A类 A3赛题

**技术基座**：讯飞星火大模型（Spark-X）

---

## 第1章 系统概述

### 1.1 背景与问题

大学计算机网络课程知识体系庞杂（覆盖OSI七层、TCP/IP协议族、路由协议等20+核心知识点），学生普遍存在以下问题：
- **个体差异大**：不同学生薄弱点各异，传统"广播式"教学无法精准定位
- **学完就忘**：缺乏深度理解，考试前临时背诵后容易遗忘
- **错误认知固化**：如"TCP三次握手可以改为两次""HTTP直接运行在IP上"等常见误解长期未被纠正
- **学习资源单一**：市面资源通常只有文字描述，缺乏可视化仿真和自适应生成

### 1.2 系统定位

Socrates Cube 是面向高校《计算机网络》课程的**多智能体自适应学习辅助系统**，以谢希仁《计算机网络》第8版为核心知识来源，参考 RFC 9293（TCP）、RFC 8200（IPv6）、RFC 9110（HTTP语义）等国际标准，通过8个协同工作的AI Agent，实现从"判断对错"到"理解为什么错"的认知升级。

### 1.3 核心价值

| 传统问答系统 | Socrates Cube |
|------------|---------------|
| 只判断对/错 | 三层诊断：表面错误→根因→误区模式 |
| 统一资源推送 | 基于认知风格自适应生成5类资源 |
| 固定学习顺序 | 知识图谱驱动的个性化路径规划 |
| 静态内容 | 实时动态更新的8维能力画像 |
| 无可信机制 | RAG引用溯源+域外拦截+不确定性声明 |

### 1.4 用户群体

- 高校计算机专业学生（主要）
- 网络工程领域在职学习者
- HCIA-Datacom、CCNA等认证考试备考者

## 第2章 系统架构设计

### 2.1 总体技术架构

系统采用前后端分离的五层架构：

```
┌──────────────────────────── 表现层 ─────────────────────────────┐
│  Vue3 + TypeScript + Element Plus + TailwindCSS                │
│  25个视图页面，统一通过Pinia状态管理                              │
└────────────────────────── SSE / HTTP ──────────────────────────┘
                               ↕
┌──────────────────────────── API层 ──────────────────────────────┐
│  FastAPI 0.111 + Uvicorn 0.29 + sse-starlette 2.1             │
│  23个路由模块，JWT鉴权，请求ID追踪中间件                         │
└────────────────────────────────────────────────────────────────┘
                               ↕
┌──────────────────────────── Agent层 ───────────────────────────┐
│  OrchestratorAgent（中枢调度）                                   │
│  ├── DiagnosisAgent    ├── ProfilerAgent   ├── RetrieverAgent  │
│  ├── ResourceGenerator ├── PathPlanner    ├── ChallengerAgent  │
│  └── SimulatorAgent                                            │
└────────────────────────────────────────────────────────────────┘
                               ↕
┌──────────────────────────── 知识层 ────────────────────────────┐
│  ChromaDB向量库（3库）  SQLite/MySQL  知识图谱JSON               │
│  course_docs(30+篇)    11张业务表     20节点+87边               │
│  protocol_specs(200+)                48个ACU单元               │
│  misconceptions(24+)                 误解库24+条               │
└────────────────────────────────────────────────────────────────┘
                               ↕
┌──────────────────────────── LLM层 ─────────────────────────────┐
│  讯飞星火Spark-X（主）  ARK/Doubao兼容接口（备）                  │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 多智能体协同机制

系统采用中枢调度（Orchestrator Pattern）模式，由 OrchestratorAgent 统一接收用户消息，按对话状态机决定激活哪些下游Agent，通过 SSE（Server-Sent Events）将各Agent的执行过程实时推送给前端。

**对话状态机**（四态）：
- `idle`：等待输入
- `learning`：正常学习问答循环（Retriever→Diagnosis→Profiler→ResourceGenerator→PathPlanner）
- `consolidation`：累计5轮学习后自动触发ChallengerAgent巩固检验
- `planning`：完成3个知识点后触发路径重规划

**SSE事件类型**（13种）：
`agent_start / agent_end / token / diagnosis / resource / path_update / state_change / persona_set / scope_notice / done / error / tool_call / heartbeat`

### 2.3 流式输出架构

对话核心接口 `POST /api/v1/chat/stream` 采用异步生产者-消费者模式：
- **生产者**：`_produce()` 协程驱动各Agent依次执行，将结果压入 asyncio.Queue
- **消费者**：`event_generator()` 从队列读取并输出 SSE 帧
- **心跳保活**：每15秒发送 `: heartbeat\n\n` 防止代理超时断连
- **防二次包装**：使用 StreamingResponse 而非 EventSourceResponse，避免SSE帧被二次包装

## 第3章 三大核心创新点

### 3.1 三层认知诊断框架

区别于传统问答系统仅判断"对与错"，本系统参考教育心理学中的认知负荷理论与错误分析框架，实现三层递进式诊断：

**L1 表面错误识别**

通过 LLM 提示词 + 关键词规则检测9种错误类型：

| 错误类型 | 说明 | 典型案例 |
|---------|------|---------|
| flow_omission | 流程步骤遗漏 | 认为TCP两次握手即可 |
| layer_misplacement | 层级归属错误 | 认为HTTP直接运行在IP上 |
| concept_confusion | 概念混淆 | 混淆递归查询和迭代查询 |
| field_misunderstanding | 字段理解错误 | 把/24误解为24个主机地址 |
| reasoning_breakdown | 推理断裂 | 因果关系倒置 |
| factual | 事实性错误 | IP地址位数记错 |
| security_misconception | 安全误解 | |
| performance_confusion | 性能混淆 | |
| over_simplification | 过度简化 | 认为UDP完全没有用途 |

**L2 根因溯源**

结合知识图谱上下文，通过 LLM 分析错误的深层原因和缺失的前置知识，支持多根因排序，输出 `root_causes`（根因列表）和 `missing_prerequisites`（缺失前置知识点）。

**L3 误区模式匹配**

将学生错误映射到 24+ 条已知误解模式库（通过向量检索），生成对应的干预建议，包括：仿真纠偏（simulation）、对比题练习（contrast_table）、知识文档（doc）、追问引导（follow_up_question）。

**诊断输出示例**：
```json
{
  "is_correct": false,
  "confidence": 0.87,
  "surface_error": "认为TCP两次握手足够建立连接",
  "error_type": "flow_omission",
  "root_causes": ["对全双工确认机制理解不足"],
  "missing_prerequisites": ["kp_013"],
  "pattern": "握手次数混淆",
  "intervention_suggestion": "建议通过TCP三次握手仿真动画直观理解各步骤的必要性",
  "related_node_ids": ["kp_014", "kp_013"]
}
```

### 3.2 KP-ACU双层知识图谱

#### KP层（宏观结构）
20个课程知识节点，按教材第1-7章组织，每个节点包含：节点ID、名称、所属章节、类型（concept/protocol/skill）、难度（1-5）、预计学习时间（分钟）、关键词、描述。

**节点分布**：
- 第1章：kp_001（网络概述）、kp_002（OSI七层）、kp_003（TCP/IP体系结构）
- 第2章：kp_004（物理层）
- 第3章：kp_005（数据链路层）、kp_006（局域网技术）
- 第4章：kp_007~kp_010（网络层、IP地址、ARP、路由协议）
- 第5章：kp_011~kp_015（运输层、UDP、TCP基础、三次握手、拥塞控制）
- 第6章：kp_016~kp_018（应用层、DNS、HTTP/HTTPS）
- 第7章：kp_019~kp_020（网络安全、综合应用）

#### ACU层（微观原子点）
48个认知理解单元（Atomic Cognitive Units），将KP节点细粒度分解，例如：
- kp_014（TCP三次握手与四次挥手）→ acu_025（三次握手各步骤）+ acu_026（四次挥手各步骤）

#### 图谱依赖关系
87条有向边表示前置依赖，PathPlannerAgent 通过拓扑排序（Kahn算法）确定学习顺序，确保学生先学前置知识再攻目标知识点。

#### 与误解库的映射
每条误解记录（mc_001~mc_024+）都与 ACU 和 KP 节点双向映射，支撑 DiagnosisAgent 在L3阶段的精准误区模式匹配。

### 3.3 混合更新画像策略

**8个能力维度**：

| 维度 | 字段 | 说明 |
|------|------|------|
| 概念理解 | conceptual_understanding | 概念定义和辨析能力 |
| 协议分析 | protocol_analysis | 协议头部结构分析能力 |
| 计算能力 | calculation_ability | 地址计算、序号推导能力 |
| 错误诊断 | error_diagnosis | 识别和分析错误的能力 |
| 系统设计 | system_design | 综合运用知识设计方案的能力 |
| 知识关联 | knowledge_connection | 跨知识点迁移应用能力 |
| 表达清晰 | expression_clarity | 语言组织和表达能力 |
| 自我修正 | self_correction | 发现并纠正自身错误的能力 |

**混合更新策略**：
- **确定性增量更新**（每轮对话）：根据诊断结果直接调整相关维度分数和掌握度，无需LLM调用，延迟 <50ms。例如：诊断出 flow_omission 类型错误 → 降低 protocol_analysis 和 conceptual_understanding 维度分数
- **LLM全量校准**（每5轮触发）：调用讯飞星火API对完整对话历史进行画像重评估，带10秒去抖窗口防止频繁调用

## 第4章 功能设计

### 4.1 智能对话系统

用户可通过自然语言与系统交互，询问计算机网络相关问题。系统特性：
- **4种人格切换**：professor（学术严谨）、engineer（工程实践）、peer（学长轻松）、interviewer（面试模拟）
- **苏格拉底式追问**：不直接给答案，通过引导性问题促进深度思考
- **执行链路可视化**：前端实时展示各Agent的执行过程和耗时
- **域外拦截**：非计算机网络领域问题自动拦截并提示

### 4.2 认知诊断面板

专门针对学生回答进行三层诊断，展示：
- 诊断置信度
- 错误类型分类
- 根因分析结果
- 推荐干预措施（仿真/练习/文档）

### 4.3 8维能力画像

以雷达图形式实时展示8个能力维度的当前水平，同时展示：
- 20个KP知识点的掌握度热力图
- 薄弱点列表（掌握度<0.5的知识点）
- 优势点列表（掌握度>0.8的知识点）
- 学习成长报告（综合得分、证书推荐路径）

### 4.4 个性化学习路径

基于知识图谱拓扑排序生成"最短补偿路径"，每个节点附：
- **三维推荐理由**：图谱依赖 + 诊断结果关联 + 认知风格匹配
- **动态节点状态**：completed / in_progress / pending / locked
- **预估学习时长**
- **推荐资源类型**

### 4.5 五类学习资源生成

根据诊断结果和认知风格自适应生成：

| 资源类型 | 说明 | 适合认知风格 |
|---------|------|------------|
| doc（知识文档） | Markdown格式知识点总结，含RFC引用 | textual型 |
| exercise（练习题） | 含答案与解析的练习题组 | practical型 |
| code（代码示例） | 协议实现代码+详细注释 | practical型 |
| mindmap（思维导图） | Mermaid语法可渲染的导图 | visual型 |
| script（教学脚本） | 分步讲解的视频脚本JSON | visual型 |

### 4.6 协议仿真实验室

基于HTML5 Canvas技术实现7个交互式协议动画场景：
1. TCP三次握手
2. TCP四次挥手
3. TCP滑动窗口机制
4. TCP拥塞控制（慢启动→拥塞避免→快恢复）
5. HTTP请求/响应流程
6. DNS递归查询与迭代查询
7. 数据封装与拆封过程

### 4.7 概念挑战系统

通过苏格拉底式追问检验学生对知识点的真实理解：
- 触发条件：诊断发现错误 OR 连续5轮学习后
- 追问轮次：最少2轮，最多5轮
- 自适应策略：答对→提升难度；答错→降维引导
- 内置兜底题库：3道经典题（TCP握手/UDP vs TCP/ARP与MAC）

### 4.8 知识库功能

- PDF智能知识库：支持上传教材PDF，自动提取文本入库，支持语义搜索和问答
- 教材书库：展示系统内置计算机网络相关教材，支持章节阅读
- AI图谱助手：ECharts可视化知识图谱，支持节点查询和关系探索

## 第5章 AI集成应用说明

### 5.1 讯飞星火大模型集成

系统主要使用讯飞星火 Spark-X 模型（wss://spark-api.xf-yun.com/x2），通过 spark-ai-python SDK（≥0.4.5）进行集成。

**集成方式**：
- 同步调用：`llm_client.chat(prompt, max_tokens)` 用于 Diagnosis/Profiler/Challenger等需要结构化输出的场景
- 流式调用：通过 SSE 机制实现对话流式推送

**多人格路由**：根据前端选择的 `agent_persona` 参数，为每种人格配置不同的系统提示词前缀（config/agent_personas.json），使同一模型表现出不同的教学风格。

**备用LLM**：当需要更强的多轮对话或批量生成能力时，系统支持切换到 ARK/Doubao 兼容接口（doubao-pro-32k），通过统一的 OpenAI 兼容接口调用。

### 5.2 RAG知识增强架构

```
用户问题
    ↓
RetrieverAgent → ChromaDB向量检索
    ├── course_docs（课程文档，30+片段）
    ├── protocol_specs（RFC规范，200+片段）
    └── misconceptions（误解库，24+条）
    ↓
检索到的相关文档（Top-K）
    ↓
DiagnosisAgent/ResourceGeneratorAgent
将检索结果注入Prompt → 调用LLM生成答案
    ↓
输出含引用溯源的结构化结果
```

知识库构建流程：
1. `scripts/download_knowledge_sources.py` - 下载RFC文档
2. `scripts/ingest_docs.py --reset` - 文本分块（按章节标题，chunk_size=900，overlap=140）并写入ChromaDB

### 5.3 可信机制设计

**域外拦截**：`trust_mechanism.check_question_scope()` 检测问题是否属于计算机网络领域，超出范围时返回提示信息，不调用LLM。

**引用溯源**：所有基于知识库的回答都在响应中附带来源文档片段（related_docs），用户可追溯每个知识点的来源。

**不确定性声明**：当 LLM 对某个知识点的置信度较低时，系统主动在回答中声明不确定性，避免将模糊知识作为确定事实呈现。

**降级容错**：LLM超时或返回非法JSON时，各Agent有对应的降级策略（返回默认值而非抛异常）。

## 第6章 技术实现细节

### 6.1 后端关键实现

**项目结构**（src/loopse/）：
```
agent/          - 8个Agent实现
├── orchestrator.py  (572行) - 中枢调度
├── diagnosis.py     (381行) - 三层诊断
├── profiler.py      (362行) - 8维画像
├── resource_generator.py (660行) - 资源生成
├── path_planner.py  (304行) - 路径规划
├── challenger.py    (517行) - 概念挑战
├── retriever.py     - 知识检索
└── simulator.py     - 协议仿真
api/            - 23个FastAPI路由模块
core/           - LLM客户端、可信机制
db/             - SQLAlchemy模型与仓库
kb/             - 知识库、知识图谱、误解库
schema/         - Pydantic数据结构
```

**异常处理策略**：
- DiagnosisAgent：确保 pattern 始终为 dict、root_causes 始终为 list，不向上抛异常
- ProfilerAgent：LLM返回非法JSON时回退到默认画像
- OrchestratorAgent：LLM超时或Agent异常时自动降级，保证主流程不中断

### 6.2 前端关键实现

**SSE对接**：使用原生 EventSource API，通过 composables/useSSE.ts 封装，按 event 字段分发处理各类Agent事件。

**状态管理**：Pinia stores 持久化（pinia-plugin-persistedstate）至 localStorage，保证刷新后认证状态和用户画像不丢失。

**路由守卫**：双层拦截——未登录跳/login；已登录但未完成AI引导跳/onboarding。

### 6.3 数据库设计要点

**混合存储策略**：
- 结构化数据（用户信息、测评记录）→ 关系型表
- 复杂嵌套数据（8维画像、会话消息、路径节点）→ JSON列（Text类型）+ ORM层反序列化
- 知识图谱 → JSON文件（data/knowledge_graph.json），运行时加载到内存

**两套数据库方案**（环境变量切换）：
- 开发：`DATABASE_URL=sqlite:///./edu_agent.db`
- 生产：`DATABASE_URL=mysql+pymysql://...`

## 第7章 系统局限性与改进方向

### 7.1 当前局限性（如实说明）

**域外检测准确性**：当前域外检测基于关键词规则，对于边界问题（如"计算机网络与密码学交叉话题"）的判断准确率有待提升。

**RL优化模块**：系统集成了LinUCB上下文赌博机（资源推荐）和DQN路径节点选择器（路径规划）两个RL模块，但均为软依赖——当相关依赖不可用时自动降级到规则策略。在竞赛演示环境中，RL模块的训练数据积累不足，实际效果与规则策略差异尚不显著。

**虚拟教师TTS**：依赖讯飞超拟人语音合成API，无有效API Key时降级为纯文字展示。

**PDF解析精度**：MinerU高精度PDF解析（公式/表格识别）为可选依赖，演示环境中使用PyMuPDF降级方案，复杂公式场景的解析精度受限。

**知识图谱覆盖度**：当前20个KP节点覆盖《计算机网络》教材主干知识，部分细粒度知识点（如BGP AS路径属性细节）尚未独立建模。

### 7.2 未来改进方向

1. **扩展知识图谱**：将KP节点从20个扩展至50+个，细化ACU粒度，提升诊断精度
2. **完善域外检测**：引入意图分类模型，提高边界判断准确率
3. **RL模块实装**：积累真实用户交互数据，训练LinUCB/DQN模型，实现真正的自适应优化
4. **跨平台适配**：适配移动端浏览器，支持手机学习场景

# 1. 克隆项目
