# 文档生成规划（Document Generation Plan）

> 本文件规划 Socrates-Cube 软件杯参赛文档的完整生成方案
> 基于：PROJECT_KNOWLEDGE_BASE.md（项目知识）+ SOFTWARE_CUP_DOCUMENT_RULES.md（规范约束）
> **⚠️ 提交截止：2026年7月20日（今日）15:00**

---

## 一、生成架构原则

```
PROJECT_KNOWLEDGE_BASE.md    SOFTWARE_CUP_DOCUMENT_RULES.md
        │                                │
        └──────────────┬─────────────────┘
                       ↓
              文档生成（Qoder执行）
                       ↓
            docs/final/（正式文档目录）
```

**铁律**：
- 每份文档的每个数据点，必须能在 PROJECT_KNOWLEDGE_BASE.md 找到来源
- 每份文档的格式，必须符合 SOFTWARE_CUP_DOCUMENT_RULES.md 约束
- 禁止虚构：不存在的功能不写、未实现的能力不夸大

## 四、执行方式

### 4.1 生成单个文档的标准提示词模板

```
请生成 Socrates-Cube 的《[文档名称]》。

约束来源：
- 项目知识：docs/repowiki/PROJECT_KNOWLEDGE_BASE.md
- 规范要求：docs/repowiki/SOFTWARE_CUP_DOCUMENT_RULES.md

生成原则：
1. 所有数据必须来自PROJECT_KNOWLEDGE_BASE，不得虚构
2. 格式遵循SOFTWARE_CUP_DOCUMENT_RULES中的规范要求
3. 对于不确定的实现细节，如实说明"待确认"或"基于代码分析推断"
4. 系统局限性章节需如实描述软依赖和未完成项

目标文档结构：
[填入上方对应文档的章节结构]

输出格式：Markdown，保存到 docs/final/XX_文档名.md
```

## 五、质量检查清单

每份生成文档完成后，对照以下清单验证：

- [ ] 所有数字（Agent数量/KP节点数/版本号）与知识库一致
- [ ] 不含虚构内容（如不存在的功能/虚假性能数据）
- [ ] 系统局限性已如实说明
- [ ] 三大创新点表述准确
- [ ] 格式符合GB/T 8567-2006规范
- [ ] 术语全文一致（统一用"认知诊断"不能混用"知识诊断"等）
- [ ] 包含封面页信息（系统名称/版本/日期）
