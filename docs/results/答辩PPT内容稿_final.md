## Slide 3｜解决思路与系统理念

### 标题
Socrates-Cube 的设计哲学：认知闭环驱动

### 核心理念（三项）

**① 诊断先行（Diagnosis-First）**  
→ 先精准识别学生的认知状态，再生成针对性干预方案

**② 认知闭环（Cognitive Loop）**  
→ 诊断 → 资源生成 → 路径规划 → 画像更新 → 下一轮诊断

**③ 可解释 AI（Explainable AI）**  
→ 每一项推荐均附带来源、置信度和推理依据，不做"黑盒"输出

### 核心创新对照表

| 传统智能问答 | Socrates-Cube |
|------------|--------------|
| 单轮问答，无记忆 | 多轮对话，持续更新八维画像 |
| 输出结论，不解释原因 | 三层诊断 + 可溯源引用 |
| 静态资源链接 | 基于误区实时生成五类个性化资源 |
| 无学习路径 | 知识图谱驱动的可解释路径规划 |

### 视觉建议
- 中央：认知闭环圆形示意图（诊断→资源→路径→画像→诊断）
- 四象限与 Agent 名称对应标注

### 讲解词（40s）
> "我们的设计哲学是'认知闭环驱动'。系统的核心逻辑是：先通过三层诊断精准识别学生的认知误区，再基于误区结果生成个性化资源，并在知识图谱上规划最优学习路径，每一步推荐都有可溯源的解释依据——这与传统黑盒 AI 的核心区别，在于我们做到了可解释的教育 AI 闭环。"

## Slide 5｜创新点一：三层认知诊断引擎 ⭐⭐⭐

### 标题
创新点一：三层递进认知诊断引擎

### 三层架构详解

**第一层：表层错误识别（Surface Error Detection）**
- 识别 7 种错误类型：流程遗漏 / 层级错位 / 概念混淆 / 参数错误 / 因果颠倒 / 范围越界 / 术语误用
- 置信度校准系统（0–100%），四色编码（绿/蓝/黄/红）
- 快速关键词预筛 + LLM 精细判断的双层设计

**第二层：根因溯源分析（Root Cause Analysis）**
- 关联知识图谱，追溯缺失的前置知识点
- 多根因排序（按影响程度 0–1.0 降序）
- 输出：`missing_prerequisites` 知识点 ID 列表

**第三层：误区模式匹配（Misconception Pattern Matching）**
- 60+ 条误解库，覆盖 7 种模式类型 + 混合模式
- 自动匹配最相近的误区模式
- 输出：干预建议（仿真纠偏 / 对比题练习 / 步骤拆解）

### 典型诊断示例
```
学生输入："TCP只需要两次握手就能建立连接"

第一层：error_type = "flow_omission"，confidence = 0.94
第二层：root_causes = ["TCP可靠性机制", "连接状态机"]
第三层：pattern = "流程省略型"
         intervention = "建议通过协议仿真观察第三次ACK丢失后的行为"
```

### 视觉建议
- 漏斗图三层展示 + 右侧实际系统截图（诊断面板）
- 底部数据标注：误解库 60+ 条，知识点覆盖率 100%（20/20）

### 讲解词（75s）
> "我们最核心的创新是三层认知诊断引擎。传统 AI 问答只能判断对错，但我们做到了三个层次的深度分析。第一层识别错误类型，我们定义了 7 种错误分类，并对每项诊断输出置信度——这是可解释性的基础。第二层进行根因溯源，系统会在知识图谱中找到缺失的前置知识点，告诉学生'你之所以犯这个错，是因为这个底层概念没有掌握。第三层进行误区模式匹配，从 60 多条误解库中找到最接近的模式，给出针对性干预建议。右边这张截图是真实系统的诊断面板，您可以看到三层结果的完整展示。"

## Slide 6｜创新点二：多表征自适应资源生成 ⭐⭐

### 标题
创新点二：诊断驱动的五类个性化资源生成

### 五类资源对照表

| 资源类型 | 格式 | 适合认知风格 | 生成依据 |
|---------|------|------------|---------|
| 知识文档（Doc） | Markdown 结构化文档 | 阅读型 | 检索结果 + 知识图谱 |
| 练习题（Exercise）| 选择/填空/简答题 | 刷题型 | 误区类型 → 题型映射 |
| 代码示例（Code） | Python/C Socket 示例 | 动手型 | 知识点 + 难度分级 |
| 思维导图（MindMap）| Mermaid 可渲染图 | 视觉型 | 知识图谱子图提取 |
| 视频脚本（Script） | 分镜 + 解说词 | 视听型 | 翻转课堂场景设计 |

### 自适应逻辑
```
误区类型 → 题型映射
  flow_omission  → 流程排序题 + 步骤填空
  concept_confusion → 对比辨析题 + 属性对照
  param_error    → 数值计算题 + 参数范围练习

认知风格 → 资源优先级
  视觉型  → MindMap 优先
  动手型  → Code 优先
  阅读型  → Doc 优先
```

- 五类资源卡片横排展示（对应 Tab 截图）
- 右侧：误区→题型映射关系图

### 讲解词（50s）
> "第二个创新是诊断驱动的五类个性化资源生成。系统根据三层诊断结果，自动决定生成什么类型的资源：如果学生的错误是流程遗漏，优先生成步骤排序题；如果是概念混淆，优先生成对比辨析题。同时，系统还会考虑学生的认知风格——视觉型学习者优先推思维导图，动手型优先推代码示例。这实现了资源生成的双重个性化。"

## Slide 7｜创新点三：可解释知识路径规划 ⭐⭐

### 标题
创新点三：知识图谱驱动的可解释学习路径

### 技术实现

**知识图谱结构**
- 100 个知识节点（覆盖 OSI/TCP-IP/HTTP/DNS/TLS 等核心知识域）
- 82 条有向依赖边（表示前置知识关系）
- RFC 标准引用：RFC 793/791/768/9293/9110/9112 等 11 份

**Kahn 拓扑排序路径规划**
```
输入：学生画像（掌握度 mastery_map）+ 弱点列表
处理：Kahn 算法生成拓扑有序序列
       → 过滤已掌握节点（mastery > 0.8）
       → 弱点节点优先排序
输出：最优学习顺序（含预估学习时间）
```

**三维推荐理由（可解释性核心）**
| 维度 | 内容 |
|------|------|
| 图谱依赖 | "该节点依赖 [TCP基础] 和 [端口概念]，您尚未完成" |
| 诊断结果 | "上次诊断在 TCP 连接管理处出现 flow_omission 错误" |
| 认知风格 | "您偏好视觉型学习，该节点有配套协议仿真资源" |

### 视觉建议
- 左侧：知识图谱可视化截图（ECharts 渲染）
- 右侧：PathTimeline 路径时间线 + 三维理由弹窗截图

### 讲解词（60s）
> "第三个创新是可解释的知识路径规划。我们构建了一个包含 100 个节点、82 条依赖边的计算机网络知识图谱，通过 Kahn 拓扑排序算法确定学习顺序。但这还不够——我们还为每个推荐节点提供三维推荐理由：它告诉学生'为什么要先学这个'，理由来自图谱的前置依赖关系、上一次诊断中发现的薄弱点，以及学生自己的认知风格。这是目前业界少有的教育推荐可解释性实践。"

## Slide 9｜八 Agent 协同调度机制

### 标题
星形拓扑多 Agent 协同架构

### Agent 职责矩阵

| Agent | 职责 | 输入 | 输出 |
|-------|------|------|------|
| OrchestratorAgent | 意图分类、多 Agent 调度、SSE 推送 | 用户消息 | 调度计划 + SSE 事件流 |
| RetrieverAgent | 三库联合检索 + 查询扩展 | 问题关键词 | top-5 知识片段 |
| DiagnosisAgent | 三层认知诊断 | 学生回答 | 诊断 JSON |
| ProfilerAgent | 八维画像增量/全量更新 | 对话轮次数据 | 更新后的画像 |
| ResourceGeneratorAgent | 五类资源生成 | 知识点 + 难度 + 风格 | 资源卡片 |
| PathPlannerAgent | 拓扑排序路径规划 | 学生画像 | 学习路径 |
| ChallengerAgent | 苏格拉底式追问 | 知识点 | 追问题目 |
| TrustMechanism | 域外拦截 + 来源标注 + 不确定声明 | LLM 输出 | 可信回复 |

### SSE 事件流机制

系统通过 Server-Sent Events 实现实时协作可视化：
```
事件类型：
  agent_start   → AgentStatusBar 激活对应 Agent 图标
  token         → 主对话区逐字流式输出
  diagnosis     → 右侧诊断面板弹出
  profile       → 雷达图更新动画
  resources     → 资源卡片渲染
  path          → 路径时间线更新
  done          → 全流程完成信号
```

### 讲解词（45s）
> "八个 Agent 采用星形拓扑协同，OrchestratorAgent 是中枢，负责意图分类和调度。每次用户发送消息，Orchestrator 会根据意图决定激活哪些 Agent——比如检测到错误时才触发 Diagnosis，资源不足时才触发 ResourceGenerator，避免不必要的开销。Agent 的执行过程通过 SSE 实时推送到前端，用户可以在 AgentStatusBar 中看到每个 Agent 的工作状态——这就是多 Agent 协同的可解释性。"

## Slide 10｜可信 AI 三重保障机制

### 标题
可信 AI：三重保障防止幻觉与越界

### 三重机制详解

**第一重：域外拦截（DFP 域过滤策略）**
- 快速关键词预筛 → 非计算机网络领域问题直接拒绝
- LLM 二次判断（domain_check prompt）→ 边界案例精细处理
- 拦截示例："帮我写一首诗" → 直接返回"本系统专注于计算机网络学习，无法处理该请求"

**第二重：来源溯源标注**
- 每条 LLM 回复附带参考来源编号（如 `[1] RFC 9293 §3.4`）
- 三库检索结果按相关度排序，引用高置信度片段
- 末尾自动追加参考来源列表

**第三重：不确定性声明**
- 诊断置信度 < 0.6 时，自动追加"以下诊断仅供参考，建议与教师确认"
- LLM 生成内容中的推测性表述自动添加置信度说明

### 视觉建议
- 三重机制圆圈嵌套图（由外到内：域外拦截 → 来源溯源 → 不确定声明）
- 右侧：越界拦截截图
