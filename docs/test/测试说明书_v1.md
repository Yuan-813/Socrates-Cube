## 1 引言

### 1.1 编写目的

本文档是 Socrates-Cube 系统的软件测试说明书，依据 GB/T 8567-2006 § 5.9 及 GB/T 15532-2008《计算机软件测试规范》编制。文档全面描述系统的测试策略、测试环境要求、各层级测试用例及测试结果，供测试人员执行测试及评审专家验证系统质量之用。

### 1.2 背景

**项目名称：** Socrates-Cube 多智能体自适应网络协议学习系统  
**测试范围：** 覆盖后端 9 个 Agent、REST API 层、前端 Vue3 应用、系统集成链路及性能/安全指标  
**测试执行周期：** 2026-05-01 至 2026-07-19  

### 1.3 定义与缩略词

| 术语 | 定义 |
|------|------|
| UT | Unit Test，单元测试 |
| IT | Integration Test，集成测试 |
| ST | System Test，系统测试 |
| PT | Performance Test，性能测试 |
| SEC | Security Test，安全测试 |
| Mock 模式 | 无外部 LLM API 时的本地模拟响应模式 |
| SSE | Server-Sent Events 服务端推送事件流 |
| Pass/Fail | 测试用例通过/失败状态 |
| P0~P3 | 缺陷优先级，P0 最高 |

### 1.4 参考资料

1. GB/T 8567-2006《计算机软件文档编制规范》

## 4 测试方法与策略

### 4.1 总体测试策略

采用分层递进测试策略：单元测试 → 集成测试 → 系统测试，辅以性能测试和安全测试。

```
测试层级     | 自动化程度 | 执行工具        | 覆盖目标
-------------|-----------|-----------------|------------------
单元测试      | 100%      | pytest          | 函数/类级逻辑正确性
集成测试      | 70%       | pytest+requests  | API 接口与 Agent 协同
系统测试      | 手工为主   | 浏览器 + Postman | 完整用户场景验收
性能测试      | 手工       | Chrome DevTools  | 响应时间与资源占用
安全测试      | 手工       | 浏览器 + curl    | 注入防护与越界拦截
```

### 4.2 测试执行方式

**后端自动化测试（pytest）：**

```bash
# 执行全部单元测试
cd d:/git-projects/Socrates-Cube
.venv_new\Scripts\python.exe -m pytest tests/ -v --tb=short

# 执行特定模块
.venv_new\Scripts\python.exe -m pytest tests/unit/test_diagnosis_layer3.py -v
```

**前端验证：**

```bash
cd frontend
npm run type-check   # TypeScript 类型检查
npm run build        # 构建验证（无错误为通过）
npm run dev          # 启动开发服务器（手工测试）
```

**Mock 模式全链路测试：**

```bash
# 启动 Mock 模式后端
set MOCK_MODE=1
uvicorn src.loopse.main:app --host 0.0.0.0 --port 8000
```

### 4.3 测试数据管理

| 数据类型 | 来源 | 存放位置 |
|---------|------|---------|
| 演示用学生回答 | 人工设计（含典型错误） | `tests/unit/` 测试文件内 |
| Mock SSE 数据 | 手工编写 | `frontend/public/mock/*.json` |
| 预置演示账号 | `scripts/demo_warmup.py` 生成 | SQLite `edu_agent.db` |
| 知识图谱测试数据 | `data/knowledge_graph.json` | 项目 data/ 目录 |
