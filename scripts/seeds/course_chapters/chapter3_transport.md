# 第3章 传输层

Collection: course_docs
Chapter: chapter3
Focus: TCP、UDP、三次握手、四次挥手、可靠传输与拥塞控制

## 传输层提供的服务

传输层在网络层提供的主机到主机通信基础上，进一步提供应用进程到应用进程的端到端通信。核心服务包括复用与分用、差错检测、按序交付、流量控制和拥塞控制。端口号用于区分同一主机上的不同应用进程，例如 HTTP 常用 80/443，DNS 常用 53。

## UDP 协议特点

UDP 是无连接、尽最大努力交付的传输协议，首部开销小、无拥塞控制，适合实时音视频、DNS 查询、QUIC 底座等场景。UDP 不保证可靠、按序和流量控制，可靠性需由应用层自行实现。认为"UDP 完全没用"是常见误区，实际上很多高性能协议故意选择 UDP 以减少内核状态。

## TCP 报文段结构

TCP 首部包含源端口、目的端口、序号、确认号、数据偏移、标志位、窗口、校验和等字段。标志位 SYN、ACK、FIN、RST、PSH、URG 共同描述连接状态和数据交互语义。序号按字节流编号而非按报文段计数，这一点直接影响对重传、乱序和确认机制的理解。

## TCP 连接建立：三次握手

三次握手过程为：客户端发送 SYN，服务器回复 SYN-ACK，客户端再发送 ACK。第三次 ACK 用于确认客户端已收到服务器的 SYN-ACK，避免历史重复连接请求导致服务器错误分配资源。仅两次交互不足以建立双向可达的可靠连接状态，因此教材和 RFC 均强调三次握手。

## TCP 连接释放：四次挥手

TCP 是全双工通信，连接关闭需要双方分别关闭自己的发送方向。典型过程是 FIN-ACK-FIN-ACK 四次交互。主动关闭方进入 TIME-WAIT 状态，等待 2MSL 以确保最后的 ACK 可达并处理迟到报文。把"断开连接一定是三次"与握手混淆，是初学者常见错误。

## 可靠传输机制

TCP 通过序号、确认、超时重传、快速重传和校验实现可靠传输。接收方用累积确认或选择确认 SACK 指示已成功接收的字节范围。超时重传依赖 RTT 估计，快速重传通常在收到三个重复 ACK 时触发。仅有 ACK 机制并不意味着不会丢包，丢包后要靠重传恢复。

## 流量控制

流量控制保护接收方不被过快发送的数据淹没。TCP 使用接收窗口 rwnd 告知发送方可接收的字节数。发送方实际发送窗口受 rwnd 和拥塞窗口 cwnd 共同约束。把流量控制与拥塞控制混为一谈是常见误区：前者关注接收端缓存，后者关注网络路径容量。

## 拥塞控制概述

拥塞控制通过慢启动、拥塞避免、快重传和快恢复等算法调节发送速率。慢启动阶段 cwnd 通常按 RTT 指数增长，直到阈值或检测到丢包。拥塞信号来自超时或重复 ACK。理解 cwnd 与 rwnd 的区别，是分析高带宽长时延网络性能的关键。

## TCP 三次握手学习要点

学习三次握手时应同时掌握状态迁移、报文字段和异常场景：SYN 洪泛、半连接队列、同时打开等。教学场景中常用序列图展示客户端与服务器的 SYN-SENT、ESTABLISHED 等状态变化。回答"什么是 TCP 三次握手"时，应说明目的、步骤和每一步的必要性，而不仅是罗列报文名称。
