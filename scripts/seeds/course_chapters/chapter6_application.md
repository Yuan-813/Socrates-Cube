# 第6章 应用层

Collection: course_docs
Chapter: chapter6
Focus: HTTP、HTTPS、DNS、邮件协议与 Web 发展

## 应用层概述

应用层直接为用户应用提供服务，定义进程间通信规则。常见协议包括 HTTP、DNS、SMTP、FTP 和 WebSocket。应用层协议通常采用客户/服务器模型，依赖下层传输协议提供端到端通信。HTTP 属于应用层，通常运行在 TCP 之上，而不是直接运行在 IP 上。

## 域名系统 DNS

DNS 将人类可读的域名解析为 IP 地址，采用分布式层次数据库结构。查询方式包括递归查询和迭代查询：递归查询由被询问服务器代为继续查询；迭代查询返回下一步应询问的服务器地址。DNS 记录类型包括 A、AAAA、CNAME、MX、NS 等，各自服务不同用途。

## HTTP 基本工作方式

HTTP 是面向事务的无状态应用层协议，基于请求-响应模型。常见方法有 GET、POST、PUT、DELETE 等。状态码 1xx/2xx/3xx/4xx/5xx 表示不同语义，其中 404 表示资源未找到，不等于服务器宕机。持久连接 Keep-Alive 可减少连接建立开销。

## HTTP 报文结构与缓存

HTTP 报文由起始行、首部字段和实体主体组成。缓存可在浏览器、代理、CDN 和源站多层存在，通过 Cache-Control、ETag、Last-Modified 等机制协调新鲜度与验证。认为缓存只存在于浏览器中是过度简化。

## HTTPS 与安全传输

HTTPS 在 HTTP 与 TCP 之间引入 TLS，提供机密性、完整性和服务器身份认证。TLS 握手协商密码套件、交换密钥并验证证书链。认为 TLS 只负责加密、不负责认证，会低估其在防篡改和防中间人攻击中的作用。

## Web 发展：HTTP/2 与 HTTP/3

HTTP/2 引入多路复用、首部压缩和服务器推送等机制，缓解队头阻塞问题。HTTP/3 基于 QUIC 在 UDP 上实现传输，将连接建立、加密和拥塞控制整合，改善移动网络和高丢包环境下的性能。QUIC 是传输层协议，不是 HTTP 的别名。

## 电子邮件协议 SMTP/IMAP/POP3

SMTP 用于邮件发送，IMAP 和 POP3 用于邮件读取。SMTP 采用推模型，将邮件从客户端或中继服务器传递到目标邮件服务器。MIME 扩展支持多媒体内容与附件。邮件系统体现了应用层协议分工与存储转发思想。

## FTP 与文件传输

FTP 使用控制连接和数据连接分离的双连接模型，支持主动与被动模式。控制连接传输命令和响应，数据连接传输文件内容。虽然公网文件共享更多被 HTTP/S 取代，FTP 仍是理解应用层会话管理的经典例子。

## WebSocket 与实时通信

WebSocket 在单一 TCP 连接上提供全双工、低延迟消息通道，适合聊天、协同编辑和实时行情推送。它通过 HTTP 升级握手建立，之后脱离传统请求-响应模式。与轮询相比，WebSocket 减少了首部开销和连接管理成本。
